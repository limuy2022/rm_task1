# 阶段任务一：A 的数学样例与交接说明

## 状态与范围

已完成：起点变换的源码公式审查、离线数学核验、匀速预测预期数据。
待完成：在Ubuntu/Humble与NUC执行实际提交链验证；已有源码修改不代表ROS验收完成。

当前用户确认的规则为九列契约；本目录只用于离线数学和固定合成样例核验。

## 文件

- `A_测试输入.json`：起点、位置/速度样例、轨迹配置、非对称地图输入。
- `A_匀速轨迹预期.csv`：1800拍预期输出，无表头，九列，全部固定六位小数。
- `A_核验.py`：标准库离线核验，可选比对实际CSV；只读，不需要ROS。

## 数学约定

位置：p比赛 = Rz(-yaw0) × (p定位 - p起点)。
速度：v比赛 = Rz(-yaw0) × v定位，不包含平移。
起点为(2,-1)，朝向90°；(2,0)映射为(1,0)，(1,-1)映射为(0,1)。
压缩包内 src/gimbal_common/gimbal_common/frames.py 的 freeze_T_map_odom() 实际实现正确：t=-R×p起点。第285行组合顺序注释易误导，后续仅修正文案。
此结论是公式审查，不表示运行过该源码或ROS节点。

目标初始位置(1,2)，目标速度(0.4,-0.2)；pred=cur+(0.04,-0.02)。
底盘固定(0.5,-0.25)，建议底盘速度固定(0.3,0.4)。
目标速度与CSV中的建议速度不同。轨迹所有数据已在比赛系，不应再次变换。
合成长轨迹会超出实场，只用于接口与数学检查。

## 给 B

按合成tick输入对应状态，关闭judge输出节点的速度守卫，避免改变测试值。
CSV列顺序：pred_x,pred_y,cur_x,cur_y,base_x,base_y,vx,vy,t_tick。
只使用最小评分输出链，不启动competition总launch。
JSON地图data遵循ROS OccupancyGrid行优先顺序，先低y行；未知=-1，自由=0，占用=100。
地图转成PGM时应翻转y行序，检查非对称格子位置而非只检查文件存在。

## 给 C

在本目录执行：

```sh
python3 -B A_核验.py
python3 -B A_核验.py /实际测试文件路径.csv
```

第二条只适用于使用同一固定合成时间的测试CSV。真实调试场CSV不能直接与本文件逐行比较。
实时测试应把t0替换为测试起始时钟，并同步生成预期数据；不能用本文件固定时间测迟到。
位置/速度允许绝对误差1e-6，时间列必须与tick的六位小数格式一致。
180秒行数等于实际发出的tick数；1800只是本合成样例的确定数量。
独立读取进程测tick stamp到完整行可见的延迟，目标最大值低于60ms，官方环境文档作废线80ms。
另验地图尺寸、分辨率、origin、占用位置及PGM/YAML可加载性。
