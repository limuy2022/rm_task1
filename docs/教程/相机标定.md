# 相机标定：只在镜头或图像设置改变时使用

当前新 K/D 已收到，1440×1080 的 raw 图像参数已更新；本次不安排重新标定。只有镜头/焦距/分辨率改变，或独立测距暴露明显问题，才使用本教程。相机内参与相机到云台的安装外参不同，拍棋盘格不会得到两者之间的安装尺寸。[主办方第二课的相机标定与 PnP](https://blog.secaumene.com/teach/class-2.html)可在此处对照。

## 1 出发前把棋盘格准备好

### A先数：内角点，不是方格数

内角点是棋盘内部四个黑白格相交的位置，最外边界不算。

```text
如果横向有9个方格，内部横向交叉点就是8个；
如果纵向有7个方格，内部纵向交叉点就是6个。
所以这块板对应8×6内角点，不是9×7。
```

让棋盘长边横放，A和C分别数一遍，记录“横向内角点____，纵向内角点____”。这不是要求你们一定换成8×6；已有棋盘数多少就填多少。

套件对应位置：`gimbal-edu-tools/camera_setup/CALIBRATION.md`的“准备”；这里已按你们海康相机的情况展开，B无需再找本地文件。

### A再量：一个黑/白方格的边长

- 量打印后实物，不采用PDF上写的尺寸。
- 可跨连续4个格量总长再除以4，例如4格总长100mm，单格25mm；横向/纵向都核对。
- 横纵明显不是等边方格，或纸张起皱、翘曲、贴歪，先换平整板，不拿不规则图案强行标。
- 纸贴在硬平板上，保留棋盘外白边；拍摄中不要弯折纸面。

记录单格____毫米。启动脚本接收毫米并换算成米，例如25mm会传给原工具`--square 0.025`，避免手动写错单位。

注意：**均匀填错单格的长度，不能单独解释这次单目标定fx约1.78倍差异。** 单位/尺寸仍应正确，但本次还要核对输入图像、采图姿态、原始K与校正后P。参见[OpenCV相机标定模型](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。


## 2 B 用现有工具开始一次新标定

先按[跟踪教程](云台跟踪.md)把本包传到 NUC 并编译；包内已带 tools/run_camera_calibration.py，不再传旧标定压缩包。相机保持现有驱动运行；在远程 Ubuntu 的终端选择本包，再检查已安装标定器：

```bash
source "$HOME/ws_championship/src/47-visual-tracking/use_here.bash"
ros2 pkg prefix camera_calibration
```

应打印现有包目录。找不到时保留输出，切回原来能运行标定器的已授权选手环境；不在公用 NUC 随手安装。确认原图仍是 1440×1080，然后输入：

```bash
mkdir -p "$TRACK_WS/records"
CAL_DIR=$(mktemp -d "$TRACK_WS/records/calibration_XXXXXX")
CAL_TOOL="$TRACK_WS/tools/run_camera_calibration.py"
read -r -p "横向内角点个数：" BOARD_COLS
read -r -p "纵向内角点个数：" BOARD_ROWS
read -r -p "单格实测边长，毫米：" SQUARE_MM
python3 -u "$CAL_TOOL" --output-dir "$CAL_DIR" --cols "$BOARD_COLS" --rows "$BOARD_ROWS" --square-mm "$SQUARE_MM" 2>&1 | tee "$CAL_DIR/console.txt"
```

三个数按实物输入，例如板确实为 8×6 内角点、25mm，就填 8、6、25。应弹出棋盘窗口。无彩色角点先查数目、是否整板入镜、焦点、反光，不改参数碰运气。程序只用现有标定算法，将 SAVE 写到本队目录，禁用会改驱动的 COMMIT，不修改系统包。

## 3 C按这个顺序摆棋盘，A负责检查覆盖

整个棋盘始终留在图像内，手尽量不遮格。每换一个姿态停1—2秒，图案清晰后再换；缓慢移动，别连续晃动。

| 次序 | C怎么拿板 | A/B看什么 |
|---|---|---|
| 1：中间正对 | 放画面中央，整板大约占画面宽度一半 | 棋盘完整、彩色连线稳定；终端出现Added sample |
| 2：左与右 | 距离基本不变，移到画面左侧、右侧，各做数次 | X覆盖增加，外侧角点仍不出画面 |
| 3：上与下 | 移到画面上部、下部 | Y覆盖增加 |
| 4：四角 | 移到左上、右上、左下、右下，整板不要被裁掉 | 把边缘区域也采进去，补畸变约束 |
| 5：近与远 | 靠近到整板仍完整且清晰，再移远到角点仍清晰可辨 | Size覆盖增加，不靠切掉半张棋盘撑满画面 |
| 6：左右倾斜 | 棋盘中心大致留原处，让左边靠近相机、右边远离；再反过来 | 改变板法线方向，约20—40°作为起点，能识别更重要 |
| 7：上下倾斜 | 上边靠近相机、下边远离；再反过来 | 补另一方向的倾角，Skew覆盖增加 |
| 8：组合 | 在左/右、近/远处再做几种倾角 | 避免所有倾斜都只在画面中央 |

“左右倾斜”不是只把棋盘在纸面内转成菱形；要让板的一侧离镜头更近，另一侧更远。把书封面向左/右掀开一点，就是这个动作。

参考就在这里：[第二课的相机标定与成像细节](https://blog.secaumene.com/teach/class-2.html)。边角覆盖约束畸变，不同倾角帮助分清焦距、主点和每张板的姿态。

工具会挑选不同的样本。**摆了40次不等于入选40张**，看终端`Added sample N`实际数字。近乎一样的画面通常不会重复入选。

建议采到约40—60张有区别的有效样本，同时确保上述位置和倾角都有。归档版本的按钮条件是“入选样本≥40，或四项覆盖达到阈值”，所以四条不一定必须全满；按钮亮了也不能代替采图质量判断。不要为了凑数字一直重复中央正视图。

## 4 B点击CALIBRATE，再点SAVE

A检查边角、远近、倾斜都覆盖后，B点击CALIBRATE。保持程序运行，计算时等待。终端通常打印K、D及标定文本，图像会出现去畸变后的预览。

然后点SAVE。应该在终端看到：

```text
本队SAVE完成：/home/实际用户名/ws_championship/src/47-visual-tracking/records/calibration_.../calibrationdata_....tar.gz
已保存采集图像、ost.yaml和ost.txt；没有写入相机驱动。
```

本队入口即使点到COMMIT也会阻止写入，并提示点击SAVE。**这里只使用SAVE。** 不点击原生工具的COMMIT，因为它可能改相机驱动配置；--no-service-check本身不能禁止COMMIT。

保存完成后，在运行程序的终端按Ctrl+C退出。这个终端的CAL_DIR仍保留，继续下一步。

## 5 B检查保存文件，A看结果有没有明显问题

```bash
CAL_ARCHIVE=$(cat "$CAL_DIR/latest_saved.txt")
ls -lh "$CAL_ARCHIVE"
tar -tzf "$CAL_ARCHIVE" | sed -n '1,10p'
tar -xOf "$CAL_ARCHIVE" ost.yaml > "$CAL_DIR/ost.yaml"
cat "$CAL_DIR/ost.yaml"
```

应看到非零大小的归档，包含多张`left-0000.png`之类的棋盘图，还有ost.yaml、ost.txt。YAML中应有：

- image_width=1440、image_height=1080；
- camera_matrix的3×3 K，fx/fy为有限正数；
- distortion_coefficients的D。

不要给 fx 预设数值，也不要把两份结果平均。**这次结果是候选，尚未通过独立验收。** `projection_matrix`里的P可能和K不同，原始/image_raw的PnP要用K+D，不把P混进来。

不同版本不一定打印总体重投影RMS。你们压缩包中的实现算了它，但没有明确打印/保存该变量；GUI的linear error也不等于总体RMS。**没有看到RMS不等于标定失败，不要找不存在的一行。** 保留完整棋盘图，我可以回来计算逐图残差、检查边缘分布和异常样本。

官方建议重投影误差应在1像素以内甚至更小，可作为初筛；低误差不能单独证明真实测距正确。[主办方标定误差说明](https://blog.secaumene.com/teach/class-2.html)。

## 6 确需复核时再做第二组独立采样，别复用同一批图

若还有约10分钟，重新创建一个 CAL_DIR，再按采图/保存/检查步骤操作：创建新的CAL_DIR，重新采不同姿态，另存一包。镜头和输入设置保持不变。

A对比两次fx/fy：如果又相差几十个百分点，别随便选一份；保留两套图查退化/输入或模型问题。几%的差异也要结合误差和真实测距判断，不把“第二次接近第一次”当作唯一验收。

复采只用于确有证据需要核查时；不要求每次到实验室重标。

## 7 留一组不参与标定的测距证据

标定后先不覆盖原程序配置。C把已知黑色外边长100mm的平整ArUco码放在两个不同距离，比如约1m和2m。A写清实际尺量值及从镜头哪一基准点量，光心偏移未知就注明。

B在另一个已source本队环境的终端，每档录3—5秒原图：

```bash
ros2 bag record -o "$TRACK_WS/records/calibration_validation_near_01" /image_raw /camera_info
```

近档录完Ctrl+C，远档换名far_01再录；同名目录已有就换后缀，不覆盖。原图体积大，只录短包。/camera_info可能仍全零，因为本次没有向驱动COMMIT，这不影响保留原图与新标定文件。

这批ArUco不是用于求K的棋盘训练数据。回来用新K/D、旧K/D在**同一批实际图像**上解算，再和独立尺量比，才能判断哪份更适合当前相机。内参标定仍不能补出相机—IMU安装外参。

## 8 离场前交哪些文件，怎么带走

B检查整个CAL_DIR，再打包：

```bash
printf '本次目录：%s\n' "$CAL_DIR"
tar -czf "$CAL_DIR/handoff.tar.gz" -C "$CAL_DIR" session.json console.txt ost.yaml latest_saved.txt "$(basename "$CAL_ARCHIVE")"
ls -lh "$CAL_DIR/handoff.tar.gz"
```

用NoMachine下载这个handoff.tar.gz到Windows。第二组有独立目录，分别下载。短bag整目录另行带走，不只复制metadata.yaml。

A附上：棋盘实物照片、内角点数、单格实测毫米值、镜头/相机型号及状态；近远验证的实际距离和尺量基准。C附上两档目标摆放照片。

交给我的最少资料是：**完整标定归档（包含棋盘图）、session.json、console.txt，以及棋盘规格。** 要判断真实测距，再加两个距离的原图短bag和独立尺量记录。

这份教程不会自动修改原camera_team47.yaml或驱动。新结果通过核验后，我再转换成现有PnP所需配置，避免你们手抄矩阵出错。
