# 原始数据录制与离线建图

上午可以先完整录制建图所需的原始点云/IMU，中午回放重新运行LIO、调整栅格参数，下午再使用选定的地图。推荐现场同时生成粗图，确认数据有效，而不是到离场后才发现没有收到雷达。

## 1 上午怎么录

先按[比赛操作指南](比赛启动与收尾.md)启动 `bash tools/start_mapping.bash`，保持底盘静止。
另开终端进入本队目录执行：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/record.bash
```

它会自动加载环境，只订阅已有话题，不启动第二份驱动、串口或运动控制。默认目录为
`records/raw_日期_时间/`，默认录制：

- `/red_standard_robot1/livox/lidar`：完整PointCloud2消息，包含原始字段、逐点时间和header。
- `/red_standard_robot1/livox/imu`：完整雷达IMU消息。

看到两个话题的 `Subscribed` 后，**保持底盘静止再录5～10秒**，为离线LIO初始化保留静止数据；然后按现场允许的方式移动，覆盖墙角和固定障碍。结束前再静止数秒。只录传感器数据无法补出未扫区域；不要整个上午只停在原地。

默认持续录制，按Ctrl+C结束；需要自动结束时：

```bash
bash tools/record.bash --seconds 900
```

900是脚本启动后的墙钟秒数，包含订阅发现时间，不承诺恰好9000帧；现场窗口应预留保存时间。自定义目录必须是新目录：

```bash
bash tools/record.bash --output-dir "$PWD/records/raw_morning_01"
```

默认只录建图必需输入。需要额外保留相机原图、camera_info、云台IMU和epoch时：

```bash
bash tools/record.bash --with-camera
```

相机和云台话题必须由已有驱动发布；此选项不会启动它们。图像数据量大，注意磁盘空间。
没有收到的额外话题会打印出来，manifest的 `optional_topics_not_received` 也会列出；
`success=true`只表示必需的雷达/IMU录制及文件计数核验通过，不代表未启动的相机也录到了。
相机info未发布时，脚本仍保留安装的相机YAML副本。

默认备份安装的LIO、建图、装车和相机配置，以及存在的Livox JSON；如果实际运行用了自定义LIO文件，必须明确传同一个文件：

```bash
bash tools/record.bash --lio-config /实际路径/本次_lio.yaml
```

其他临时启动覆盖也要自行保留，文件副本不是运行期参数自动实测。不要只带bag而忘记标定/外参和解码配置。

## 2 怎么停止和带走

先在录制终端 **Ctrl+C一次**，等显示“原始数据保存并校验完成”，再复制文件。之后运行
`bash tools/save_mapping.bash` 保存现场粗图，最后关闭上午建图主终端。

完整目录结构：

```text
records/raw_日期_时间/
  bag/
    metadata.yaml
    bag_0.db3
    bag_1.db3 ...
  config/
    lio.yaml
    cloud_mapping.yaml
    vehicle.yaml
    camera.yaml
    livox.json（现场存在时）
  record_qos.yaml
  recorder.log
  manifest.json
```

**复制整个raw目录，不要只复制某个db3。** 默认每60秒或1GiB分片，以先达到的条件为准；
不做实时压缩，不重采样、不删帧、不重写header。录制器使用64MiB缓存，结束时等待缓存和metadata写出。

结束校验会独立查询每个SQLite分片的实际消息数并与metadata核对，必需话题为0、分片缺失、
录制器报告缓存丢失/未写完或异常退出时，返回非零并保留证据。磁盘剩余低于256MiB时提前停止并报告失败；
开始低于2GiB会提醒。消息数一致不能证明驱动/网络从未丢包，仍要看现场数据率和覆盖。

断电/强杀可能来不及生成metadata；先保留文件，在离线副本上使用 `ros2 bag reindex` 尝试恢复，不能当作已通过校验。

## 3 回来后离线建图

在自己的Humble Docker环境中操作，按[测试指南](测试运行指南.md)构建并加载 `/tmp/ci/setup.bash`。
**不启动实机Livox、不打开串口。** 使用独立ROS域，避免回放消息混入现场程序。
以下三个终端都先运行同一段环境设置，并将两个路径改为自己的实际目录：

```bash
source /opt/ros/humble/setup.bash
source /tmp/ci/setup.bash
export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=97
RAW_DIR=/workspace/records/raw_实际名称
REBUILD_DIR=/workspace/records/rebuilt_本次新编号
```

终端1：从录下的原始数据重新估计运动，不依赖原来已经算好的里程计：

```bash
ros2 launch team43_lio_backend lio.launch.py \
  use_sim_time:=true params_file:="$RAW_DIR/config/lio.yaml"
```

终端2：生成新建图配置并启动。REBUILD_DIR必须是新目录；可在新配置中调整障碍高度、分辨率等，不改原始证据：

```bash
mkdir "$REBUILD_DIR"
python3 - "$RAW_DIR/config/cloud_mapping.yaml" "$REBUILD_DIR/replay_mapping.yaml" <<'PYCFG'
import sys, yaml
with open(sys.argv[1]) as f:
    cfg = yaml.safe_load(f)
cfg['/**']['ros__parameters']['use_sim_time'] = True
with open(sys.argv[2], 'w') as f:
    yaml.safe_dump(cfg, f)
PYCFG
ros2 launch team43_bringup cloud_mapping.launch.py \
  lio_params_file:="$RAW_DIR/config/lio.yaml" \
  params_file:="$REBUILD_DIR/replay_mapping.yaml" \
  output_dir:="$REBUILD_DIR"
```

终端3：等前两节点就绪后，以0.5倍速回放原始输入并发布仿真时钟：

```bash
ros2 bag info "$RAW_DIR/bag"
ros2 bag play "$RAW_DIR/bag" --clock 50 --rate 0.5 --delay 2 \
  --topics /red_standard_robot1/livox/lidar /red_standard_robot1/livox/imu
```

必须同时启用LIO、建图的 `use_sim_time`；不能把历史header直接放到当前系统时钟下处理。
回放结束后，前两终端保持运行，在终端3请求保存：

```bash
ros2 service call /team43/save_slam_map std_srvs/srv/Trigger '{}'
```

确认 `success: true`，得到 `REBUILD_DIR/43_slam_map.pgm` 与同名YAML；检查地图后再Ctrl+C关闭前两个终端。
可以重复新建REBUILD_DIR并调整参数回放，原始bag保留不动。

## 4 下午选用离线加工地图

把选定的PGM和YAML配套复制到NUC本队目录，例如 `records/rebuilt_01/`，启动时指定：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/start_match.bash map_yaml:="$PWD/records/rebuilt_01/43_slam_map.yaml"
```

下午仍需在这张旧图中重定位，再按正式replay_start转换为比赛坐标提交。离线加工不取代下午重定位。
上午只保存，下午才统一提交；离线加工要在下午开赛前完成。
