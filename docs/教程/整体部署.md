# 完整项目上传与部署

部署单位是整个 `rm_task1` 项目。源码、配置、文档、工具、第三方子模块与 vendor
源码一起传输；NUC 重新编译自己的包，不使用个人电脑的 build/install。

配置文件按功能归属存放，路径与覆盖顺序见[配置文件归属](配置文件归属.md)。

比赛当天的终端顺序与收尾统一见[比赛启动与收尾](比赛启动与收尾.md)；本页只处理部署。

## Git 交接

1. 在自己的仓库核对 `git status` 和差异，只提交本次源码、配置和文档；不提交 build/install/log、压缩包或实验产物。
2. commit message 用中文并带 conventional 前缀，例如 `docs: 整理比赛启动手册`。提交后推送，接收方拉取同一提交并检出子模块；GitHub Desktop 可用 Changes → Commit → Push，接收方 Fetch → Pull。
3. 接收方须有私有仓库权限。双方记录同一 commit；遇到冲突先核对差异，不整份覆盖。NUC 使用下面的完整归档流程，不传个人电脑的编译产物。

## 准备完整源码归档

在个人电脑的项目根目录先检出子模块：

```bash
git submodule update --init --recursive
```

可以用压缩软件归档整个项目，也可以在 Linux/macOS 的项目根目录执行：

```bash
tar --exclude=.git --exclude=build --exclude=install --exclude=log \
  --exclude=__pycache__ --exclude=.pytest_cache --exclude=.venv \
  --exclude=output --exclude=outputs --exclude=maps --exclude=records \
  --exclude=MvSdkLog --exclude=.DS_Store \
  --exclude='*.zip' --exclude='*.bag' --exclude='*.db3' --exclude='*.mcap' \
  -czf /tmp/rm_task1.tar.gz .
```

保留仓库自带的 `archives/`、子模块和 vendor，不要把必要依赖当作实验产物排除。
上传前确认其中包含 `src/`、`tools/`、`docs/` 和 `gimbal-edu-tools/`。

## 在 NUC 的本队目录构建

通过 NoMachine 将归档上传到 NUC 的 `~/Downloads`。在 NUC Ubuntu 终端执行：

```bash
TRACK_WS="$HOME/team43_ws/rm_task1"
mkdir -p "$HOME/team43_ws"
# 已有同名目录时 mkdir 会失败；先停止旧程序、核对版本，勿叠加解压。
mkdir "$TRACK_WS" && tar -xzf "$HOME/Downloads/rm_task1.tar.gz" -C "$TRACK_WS"
```

只有成功解压后才继续。先加载 ROS 和现场已有的 Livox 工作区
`install/setup.bash`（使用现场已确认路径，不启动第二份驱动），再构建本项目：

```bash
source /opt/ros/humble/setup.bash
# 在这里 source 现场已有的 Livox 工作区 install/setup.bash
cd "$TRACK_WS"
colcon build --base-paths "$TRACK_WS/src" \
  --build-base "$TRACK_WS/build" --install-base "$TRACK_WS/install" \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
source "$TRACK_WS/install/local_setup.bash"
ros2 pkg prefix team43_control
ros2 pkg prefix team43_judge_io
```

包路径应位于本队 `~/team43_ws/rm_task1/install/`。构建范围仅为本项目的 `src`，
不在公共工作区根目录全量构建；不安装依赖、不用 pip 覆盖系统库、不修改 `.bashrc`。
若依赖缺失，保留第一个报错并核对现场已有环境。此处为 NUC 部署流程；
开发测试仍按[测试运行指南](测试运行指南.md)在 Docker 的 `/workspace` 中运行。

## 加载环境

每个新终端先加载 ROS、同一份现场 Livox 环境，再加载本项目：

```bash
source /opt/ros/humble/setup.bash
# 在这里 source 现场已有的 Livox 工作区 install/setup.bash
TRACK_WS="$HOME/team43_ws/rm_task1"
source "$TRACK_WS/install/local_setup.bash"
export ROS_LOCALHOST_ONLY=1
```

然后按[比赛启动与收尾](比赛启动与收尾.md)顺序运行。首次试转、标定和隔离域评分演练从该页链接进入。
完整上传不代表同时启动所有入口；共享的相机、雷达和串口桥各保留一份。
运动默认关闭，真实试转仍由人在参数终端显式开启。
