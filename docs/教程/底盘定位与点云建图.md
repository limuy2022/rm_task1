# 底盘定位与点云建图

只使用固定提交的 Small Point-LIO 原始核心和 `team43_lio_backend` 项目接口。
版本、算法接入与测试边界见[迁移记录](../记录/SmallPointLIO迁移验证.md)。
不启动第二份雷达驱动，不控制轮子或云台；真实底盘运动由现场人员负责。

## 1 比赛机直接编译定位包

Small Point-LIO源码直接包含在 `src/team43_lio_backend/vendor/small_point_lio/`，
没有独立安装器或额外工作区。先使用比赛机原本已加载ROS 2 Humble和Livox环境的
终端，进入本项目工作区：

```bash
colcon build --base-paths src --packages-select team43_lio_backend \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
source install/local_setup.bash
ros2 launch team43_lio_backend lio.launch.py
```

上面只编译定位包，不构建整工作区，不启动第二份驱动或电机。
若找不到 `livox_ros_driver2`，先加载现有Livox工作区的 `install/setup.bash`。
配置和外参核对见下一节。重新开终端时，加载相同Livox环境后再source本项目
`install/local_setup.bash`，不修改 `.bashrc`。

## 2 核对输入并启动定位

```bash
ros2 topic type /livox/lidar
ros2 topic echo /livox/imu --once --qos-reliability best_effort
```

点云必须是 `livox_ros_driver2/msg/CustomMsg`，具有真实逐点时间。雷达和IMU
应使用同一时间基准。静止加速度模接近1表示g单位，接近9.81表示m/s²；配置中的
`acc_norm` 和 `satu_acc` 必须同步匹配单位及实际量程。

默认参数为 `small_point_lio_mid360.yaml`，参数平铺在 `ros__parameters` 下。
核对并复制为自己的配置，固定 `extrinsic_T/extrinsic_R` 是雷达到IMU的外参，
不是底盘外参；不支持在线外参估计。

```bash
ros2 launch team43_lio_backend lio.launch.py \
  lidar_topic:=/livox/lidar imu_topic:=/livox/imu \
  params_file:=/完整路径/small_point_lio_mid360.yaml
```

实际传感器话题有命名空间时，同时替换两条输入。定位输出默认是
`/red_standard_robot1/aft_mapped_to_init` 和 `/red_standard_robot1/cloud_registered`。
位姿应为 `camera_init → body`；body是IMU参考点，不能当作底盘中心。

## 3 单独启动建图

另开终端加载相同环境，设置自己的工作区位置：

```bash
TRACK_WS="$HOME/team43_ws/rm_task1"
ros2 launch team43_bringup cloud_mapping.launch.py \
  lio_params_file:=/完整路径/small_point_lio_mid360.yaml \
  output_dir:="$TRACK_WS/maps_camera_init"
```

两份节点必须读取同一份固定外参。点云已经位于世界系，不再乘一次位姿；建图
节点用body完整姿态和雷达偏移确定射线原点。它不启动驱动、不发布TF或运动命令。
检查 `/team43/cloud_mapping/status`，确认数据更新后再按下面步骤测地面。

## 4 C 在 RViz 点地面 B 录入读到的高度

1. RViz 的 Fixed Frame 选 `camera_init`，添加 PointCloud2，话题 `/red_standard_robot1/cloud_registered`，Reliability选Best Effort。
2. B另开终端并source本包，输入：

```bash
ros2 topic echo /clicked_point
```

3. C在RViz工具栏选 **Publish Point**，在清楚可见的地面点云上点三处。不要点墙、桌面或墙脚。B记录三条消息的 `point.z`。
4. 三个值应接近，取中间值作为地面z。**这是camera_init坐标中的地面高度，不是拿尺子量的雷达离地距离。**若三处差得很大，先检查是否真的点在同一平面，不直接确认。
5. 假设实际读数为 `-0.78,-0.80,-0.79`，中间值为 `-0.79`。以下数字仅示例，必须替换为现场值：

```bash
ros2 param set /team43/cloud_mapping_node floor_z -0.79
ros2 param set /team43/cloud_mapping_node floor_confirmed true
```

下一帧开始，应显示“正在建图”，`accepted_scans`、`n_free`、`n_occupied`逐渐增长。这里只确认地面，不要求重做相机标定、O/C、完整底盘外参。

## 5 看图 保存和判断对不对

RViz添加Map，话题选 `/team43/slam_map`。应看到障碍轮廓、观察到的空闲区，以及仍为未知的区域。墙不应因雷达/底盘转向而出现另一套平行轮廓；未扫描到的地方不应凭空全变空闲。地图不自动膨胀，原始障碍和自由区保留给后续建议方向使用。

保存：

```bash
ros2 service call /team43/save_slam_map std_srvs/srv/Trigger "{}"
ls "$TRACK_WS/maps_camera_init/43_slam_map.pgm" "$TRACK_WS/maps_camera_init/43_slam_map.yaml"
```

应返回 `success: true` 并列出两个文件。默认也每10秒保存有更新的地图；Ctrl+C退出时保存最后有效地图。若没有确认过的有效地图，保存请求明确失败，不写一张看似正常的空地图。

这是 `camera_init` 中的源地图，**不是最终比赛起点地图**。正式链由现有 `team43_grid_mapper` 结合真实 `map←camera_init` 转换，再输出 `43_map.pgm/yaml`；不能只改文件名或frame标签。

初始窗口20×20m、分辨率5cm，原点[-10,-10]；实际场地更大时复制并编辑 `cloud_mapping.yaml`，启动增加 `params_file:=你的副本`。光心移出地图会报错，不循环覆盖到另一边。

默认障碍高度是地面上方0.15～1.8m，地面容差±0.08m。**这些是初始配置，不是官方规定；0.15m会漏更低的不可跨越台阶。**现场看到低障碍时，在自己的配置副本调整 `obstacle_min` 和 `ground_tolerance`，停掉建图后重新开始，别把两套地面高度混进同一张图。当前算法面向重力对齐的近似平地，不宣称已解决坡道/楼梯和长期动态建图。

本机另测20k/50k点更新约41～64ms，不含ROS；`publish_hz=1`只控制地图发布频率，不限制点云处理频率。NUC上若积压、丢帧或拖慢跟踪，保留状态和CPU现象再针对性节流。


## 6 地面与配置的两个易错点

只有还没有接受有效扫描时才能改 floor_z/floor_confirmed。输入错了、已经开始建图，就 Ctrl+C 停掉建图进程，换新输出目录重启；别把两个地面高度混成一张图。地图尺寸、障碍高度、ground_tolerance 等启动时读取，改自己的参数文件后同样要重启。

launch 的 floor_z / floor_confirmed 默认值会覆盖 YAML，所以只在 YAML 写 true 不会启用。第一次用第 4 节的 ros2 param set；后面已知地面值时可在启动命令显式加 `floor_z:=-0.79 floor_confirmed:=true`，数字用实测值。

此节点只生成源地图；有点云不等于底盘定位准确。后续由主办方驾驶时，记静止 30 秒漂移、已知距离直行、转弯和返回标记点的误差。先确认参考点是 body/IMU，再利用实测安装尺寸换到底盘中心，具体见[坐标与整车接入](坐标外参与整车接入.md)。
