# 上机调参检查清单

本表针对当前 `visual_tracking.launch.py` 图像跟踪。先按[云台跟踪](云台跟踪.md)完成传包、编译和单轴试转。旧 world 控制器的 `control.*` 不是这里的参数，别混用两套增益。

## 1 调参前确认

启动与单轴方向试验按[云台跟踪第 4 节](云台跟踪.md#4-切换到能转动的模式)执行。
确认四个方向的实际转向都让偏差减小后，再调增益；C 继续观察底座、电线和可动空间。

B 在已 source 本包 `use_here.bash` 的参数终端先停止运动：

```bash
ros2 param set /team47_tracking/visual_servo_node motion_enabled false
```

应看到 `Set parameter successful`。**一次只改一项**，改完按相同目标位置和试转条件比较。
重新试转先 false，等一秒，再 true；本次计时与积分会重新开始。

## 2 当前默认值：这些可以不重启就改

| 参数 | 默认值 | 它改变什么 / 何时才改 |
|---|---:|---|
| `kp_yaw`、`kp_pitch` | 2.0 | 偏差越大转得越快。方向正确却慢、且输出没顶到上限时，先试 3.0；来回摆先降到 1.5 |
| `kd_yaw`、`kd_pitch` | 0.0 | 根据偏差变化率抑制摆动。P 调好仍摆再试 0.05；若输出变毛躁就减小或退回 0 |
| `ki_yaw`、`ki_pitch` | 0.0 | 累积同方向残余偏差。静止目标长期偏一边，且不是死区、限幅或标定问题时，才试 0.1 |
| `filter_tau` | 0.04 s | 图像角度偏差低通。越大越平滑也越滞后；抖动时可试 0.06，跟随拖沓时可试 0.02；0 关闭 |
| `derivative_tau` | 0.05 s | 只平滑 D 的差分，不是再平滑图像；D=0 时它不影响输出 |
| `deadband_px` | 2.0 px | 中心附近小偏差不纠正。2 像素死区不能解释几十像素偏差；不要一抖就扩大到很大 |
| `max_omega` | 0.25 rad/s | 每轴速度上限；第一轮人为设 0.08。输出已顶上限时再加 P 不会更快 |
| `slew` | 1.0 rad/s² | 输出速度变化上限，减少突然加速；越小动作越缓 |
| `integral_limit` | 0.1 rad/s | I 项能贡献的最大速度，防止积累过大；Ki=0 时无作用 |
| `control_hz` | 50 Hz | 发送/状态频率，可调 20～100。检测默认 30 Hz，调到 100 不会多出图像观测 |
| `loss_grace_frames`、`loss_grace_s` | 2 帧、0.08 s | 正常丢码最多按两条限制中先到者衰减旧速度，然后停；初期可设 loss_grace_s=0 丢码即停 |
| `image_timeout`、`imu_timeout` | 0.15 s | 超过有效期停；它们不是用来掩盖数据卡顿的参数 |
| `run_seconds`、`max_rotation` | 15 s、0.35 rad | 一次试转时长和相对启动姿态幅度。0.35 rad 约 20°，不是机械限位 |
| `continuous` | false | 持续模式只解除 `run_seconds` 时间窗；位移保险丝、丢图/IMU/复位锁停全部保留。开启后人不离开参数终端 |
| `axes` | both | yaw / pitch / both，先单轴后两轴 |
| `yaw_sign`、`pitch_sign` | 1.0、1.0 | 只改对应指令方向。转向反了先停，再设该轴 -1.0；不改已确认的 IMU [1,1,1] |
| `motion_enabled` | false | 人为开启/停止本次运动；每次启动始终 false |

表中每个名字都是实际 ROS 参数。例如在运动关闭时调整 yaw 的 P：

```bash
ros2 param set /team47_tracking/visual_servo_node kp_yaw 2.0
```

按[单轴试转步骤](云台跟踪.md#41-只试左右-3-秒)复测，比较同一初始偏差下的收敛速度与摆动。
P/I/D 的输入是角度（rad）；像素误差与指令方向的换算见[控制原理](../原理/云台控制与串口.md)。

**停止：**在参数终端输入下面一条；或在启动终端 Ctrl+C 停整组程序。程序请求发零速度后停止发送；实际停转时间由本次硬件试验记录。

```bash
ros2 param set /team47_tracking/visual_servo_node motion_enabled false
```

## 3 调好了怎么保存，下次怎样恢复

B 先停止运动，选一个没有使用过的编号：

```bash
mkdir "$TRACK_WS/tuning_01"
ros2 param dump /team47_tracking/visual_servo_node --output-dir "$TRACK_WS/tuning_01"
```

应打印保存的 YAML 路径。若目录已存在换 tuning_02，不覆盖上一次。拍下/复制实际路径，重启时加 `controller_params:=那个YAML的完整路径`。例如：

```bash
bash "$TRACK_WS/run_here.bash" target_id:=0 with_bridge:=true port:=/dev/ttyUSB0 controller_params:="$TRACK_WS/tuning_01/实际生成文件名.yaml"
```

这里“实际生成文件名”必须换成上一条打印的名字。加载后仍是 motion_enabled=false，需要按步骤开启。`ros2 param set` 只修改当前进程；改源码目录的 YAML 也不会自动改已经安装的副本，改默认配置后须重新运行 `build_here.bash` 并重启。

## 4 预测噪声：先有真实轨迹，再调；改了必须重启

这些属于 `processing.launch.py` 的三维定位/二维预测，不影响上面的图像跟踪。当前保留六状态常加速度卡尔曼滤波。下列参数在节点启动时读入；`ros2 param set` 即使返回成功，已创建的滤波器也不会随之更新。应写入自己的 vehicle47.yaml 的 `/**: → ros__parameters:`，停止并重启处理链，比较同一段数据。

| 参数 | 源码默认值 | 含义与调整依据 |
|---|---:|---|
| `estimation.jerk_std` | 1.0 | 允许加速度改变的程度。越大越愿意跟上变向，也更容易追噪声；不能只凭“轨迹更平滑”判断好坏 |
| `estimation.init_sigma_p` | 0.05 m | 初始位置的不确定性，主要影响刚开始和重新跟踪 |
| `estimation.init_sigma_v` | 1.0 m/s | 初始速度的不确定性 |
| `estimation.init_sigma_a` | 5.0 m/s² | 初始加速度的不确定性 |
| `estimation.nis_gate` | 16.81 | 拒绝偏离预测过大的观测的门槛；不要为消灭报警盲目增大 |
| `perception.corner_noise_px` | 0.5 px | PnP 观测误差模型的角点噪声初值 |
| `perception.k_lat_floor` | 0.0005 | 横向位置标准差随距离增长的最低系数 |
| `perception.k_depth_floor` | 0.004 | 深度标准差随距离平方增长的最低系数 |
| `perception.force_k_lat` / `perception.force_k_depth` | 0.0 / 0.0 | 0 表示不强制覆盖上面按内参计算的系数 |
| `perception.r_min_sigma` | 0.002 m | 观测标准差下限，防止过度相信单帧 |

估计器要知道“本帧测量可能差多少”，而不是把每次 PnP 当绝对准确。代码把横向误差近似设成 `max(角点噪声/fx, k_lat_floor) × 距离`，深度误差近似设成 `max(角点噪声/(码边长×fx), k_depth_floor) × 距离²`；节点使用 0.10 m 码边长。参考[主办方第三课的预测/观测更新](https://blog.secaumene.com/teach/class-3.html)。

已有合成评估用来比较计算行为，不替代真实测距。真实轨迹怎样交给评估工具见[坐标、外参与整车接入](坐标外参与整车接入.md)。`benchmark_prediction.py --noise-std` 改的是合成观测噪声，不会修改生产节点或它的 jerk_std。

## 5 启动文件与话题对照：已核代码，现场按结果验收

| 运行项 | 输入 → 输出 | 需注意 |
|---|---|---|
| `visual_tracking.launch.py` | `/image_raw` → `/team47_tracking/marker_corners` → `/team47_tracking/cmd_vel` | 私有跟踪链；PnP 并行输出 `/team47_tracking/marker_cam`，不作为转动前置 |

| `cloud_mapping.launch.py` | 上述 cloud_registered + aft_mapped_to_init → `/team47/slam_map` | frame=camera_init；确认地面才写图，不能把 body 当底盘中心 |

话题对照用于现场核验连接关系；NUC 的实际启动、数据新鲜度和精度仍须实测。

`camera_config`、`imu_topic` 只在新图像控制器启动时读取；需要改时重启。旧 world 控制器 `control.*` 多数也是启动时缓存。建图除尚未接收有效扫描时的 floor_z/floor_confirmed 外，其它尺寸/阈值须重启；地面值的设置方法见[建图教程](底盘定位与点云建图.md)。旧 competition/sim/mapping 含历史或仿真逻辑，不作为当前实机启动命令。
