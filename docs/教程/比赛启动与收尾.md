# 比赛启动与收尾：上午建图，下午比赛

**2026-11-01新赛程：上午15分钟只建图；保存后可关闭全部程序。下午15分钟重新启动比赛程序，先在上午地图中重定位，再由裁判启动本轮客户端。上午不交地图，下午统一按正式开赛起点转换后提交。** 车辆不要求回到上午原位或朝向。上午地图与下午LIO是不同会话，程序通过点云匹配建立两者关系，绝不把两个 `lio_world` 当成同一坐标。

本队目录为 `~/ws_championship/src/43-MyDuo`。先上传并定向编译最新代码；新增了地图节点和入口，只有复制Python源码、没有重新编译安装是不够的。部署命令见[整体部署](整体部署.md#在-nuc-的本队目录构建)。Livox驱动仍由本队入口启动，相机由赛事方启动。

## 1 上午入场前准备

提前完成代码上传、Livox构建、本队包编译，避免占用15分钟。准备可备份整个 `maps/` 目录的U盘或传输位置。不要同时运行旧的start_match、独立雷达驱动或另一套LIO。

上午建议分配：前2分钟初始化、接着约10分钟覆盖场地、最后3分钟检查地图并保存备份。底盘运动由主办方/现场允许的操作完成，本队建图入口不控制底盘。

## 2 上午：一键启动独立建图

保持底盘静止完成LIO初始化，运行：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/start_mapping.bash
```

**上午不用start_match。** 此入口只启动一份Livox、Small Point-LIO和二维源建图；不启动云台串口桥、视觉运动控制或评分提交。不需要ArUco码，也不等待judge消息。终端打印本次 `records/survey_XXXXXXXX/`。

初始化后请现场人员按允许方式移动底盘，覆盖墙、角落、障碍物和比赛可能经过区域；静止时只能看到当前视野。尽量记录不同形状的墙角/固定障碍，重复、对称的房间更难在下午唯一定位。

### 查看上午地图

另开终端，先加载环境：

```bash
cd ~/ws_championship/src/43-MyDuo
source /opt/ros/humble/setup.bash
source .livox/env.bash
source install/local_setup.bash
export ROS_LOCALHOST_ONLY=1
rviz2
```

RViz中：

1. Global Options → Fixed Frame设为 `lio_world`。
2. Add → Map，Topic选 `/team43/slam_map`；Durability选Transient Local，Reliability选Reliable。
3. 可再Add → PointCloud2，Topic选 `/red_standard_robot1/cloud_registered`，Reliability选Best Effort。
4. 检查墙体与场地形状一致，没有明显重复轮廓；灰色是未观测区，不是空闲区。

本轮已采用用户授权的斜装调平及高度近似，不需要临时点地面或补外参。

### 2.1 同时保留完整原始数据

另开终端运行 `bash tools/record.bash`，看到点云和IMU均已订阅后再静止录5～10秒，然后开始移动。上午结束时先在录制终端Ctrl+C，等待校验完成，再保存地图。录制脚本不会自动随start_mapping启动；必须单独开启。
完整录制、可选相机、文件备份和中午离线重建步骤见[原始数据录制与离线建图](原始数据录制与离线建图.md)。

## 3 上午结束前：保存、交接，再停止

**建图主终端保持运行。** 在另一个终端执行：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/save_mapping.bash
```

必须看到“上午地图已保存并验证”。该脚本先请求正在运行的建图节点保存，检查地图包含占用和空闲观测，再创建独立快照：

```text
maps/survey_日期_时间/
  43_slam_map.pgm
  43_slam_map.yaml
  manifest.json
maps/current → 本次快照目录
```

下午默认加载 `maps/current/43_slam_map.yaml`，无需手填路径。`PGM+YAML`必须配套，不能只拷贝图片。快照与原始records分开，上午程序退出后仍可使用。

若保存失败，按报错修复，不停止后就默认交接完成。成功后备份：

```bash
tar -czf "records/morning_maps_$(date +%Y%m%d_%H%M%S).tar.gz" maps
```

把压缩包再传到个人电脑/U盘。最后在上午建图主终端按 **Ctrl+C**；关闭上午RViz。上午和下午不必保持同一进程或持续供电。

## 4 下午：从上午地图重新启动

确认上午程序已经结束、地图文件仍在。**底盘静止，相机水平朝车头**，运行：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/start_match.bash
```

入口默认 `map_mode=saved`，加载上午地图；不会启动第二个实时二维建图节点覆盖上午成果。新LIO仍需要实时雷达/IMU来估计下午运动，原始雷达话题保持题目规定不变。

保持底盘静止，等首次云台世界参考对齐完成，再等地图重定位。自动匹配搜索旧图的空闲区域与方向，连续三次一致且质量通过才固定对齐；状态话题为：

```bash
# 新终端先按第2节加载环境
ros2 topic echo /team43/relocalization/status \
  --qos-reliability reliable --qos-durability transient_local
```

看到 `aligned: true`，以及“重定位完成”，表示程序已建立上午地图与下午LIO的关系。日志/消息中JSON的布尔值显示为 `"aligned": true`。

下午的状态、运行参数及 `relocalization.json` 保存在 `records/match_XXXXXXXX/`。一旦对齐固定，本轮不再自动改变；需要纠正时在开赛前Ctrl+C重启，不能开赛后反复移动坐标。

### 4.1 自动匹配不唯一时，如何给大致位置

对称房间、覆盖不足或人群遮挡可能使纯点云无法唯一确定位置。看到“匹配不足或存在多解”时，保持车身静止，按以下步骤操作；这不是重新测外参。

1. 在已加载环境的终端运行 `rviz2`。
2. Fixed Frame设为 **`survey_world`**，表示上午旧图。
3. Add → Map，Topic选 **`/team43/survey_map`**，Durability选Transient Local。应能看到上午整张地图；此时尚无跨会话TF，当前点云暂时显示不了是正常的。
4. 找到车辆此刻在旧图上的大致位置。RViz顶部选择 **2D Pose Estimate**；若没有，点击工具栏“+”添加该工具，Topic保持 `/initialpose`。
5. 在地图上的**底盘中心位置**按下鼠标，拖出一根沿**车头方向**的箭头后松开。不要把箭头朝向相机光轴或雷达斜装方向。位置尽量在1米内，朝向尽量在30度内。
6. 程序改在提示附近搜索；它仍用点云检查匹配，不直接相信鼠标点击。等待 `aligned: true`。位置不对且尚未固定时可重新点击。
7. Add → PointCloud2，Topic选 `/red_standard_robot1/cloud_registered`，Reliability选Best Effort。对齐后当前点云会出现在上午地图上，检查墙/固定障碍是否重合，避免选到对称房间的另一角。

**若仍无法匹配，先不要通知裁判开赛。** 核对地点/方向、雷达点云和旧图覆盖；必要时将车辆移到更有特征的位置，静止后重试。几何完全相同的两个位置仅靠雷达无法区分，必须由现场人员提供正确的大致位置。不要为了“显示成功”随意改地图frame或把新LIO原点当成旧图原点。

### 4.2 裁判给目标ID后

先等启动参考对齐完成，再在另一终端执行，以下以ID 0为例：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/set_target.bash 0
```

检测器和PnP的ID读回应一致。默认 `motion_enabled=true`、`continuous=true`，设置目标后自动跟踪，无需另外开启。视觉跟踪与地图匹配独立，可在等待重定位期间确认指定码；通知裁判前两者都应完成。

## 5 通知裁判开赛，观察输出

**先确认：指定码跟踪正确、重定位完成且叠图正确、底盘定位持续输出。** 然后按裁判安排启动本轮客户端，比赛主终端全程保持运行。

以本轮 `/judge/replay_start` 的stamp建立正式比赛坐标原点，仍是开赛时底盘中心、车头方向，而不是上午建图起点或下午程序启动点。旧图经过已求得的跨会话变换，再转换到本轮比赛坐标，输出 `43_map.pgm/yaml`。

每个 `/judge/tick` 立即写九列CSV并刷新，时间取该拍stamp保留六位小数。客户端开赛时删除旧CSV已有处理；首拍前没有CSV属于正常情况，不用人工提前建文件。

```bash
wc -l ~/ws_championship/output/43.csv
ls -lh ~/ws_championship/output/43_map.pgm \
       ~/ws_championship/output/43_map.yaml
```

CSV行数应随评分节拍增加。**15分钟是现场给定窗口，程序不会自行在180秒或1800行停止，也不会自行向judge发拍；实际持续时间由裁判的消息决定。** 若完整15分钟都10Hz发拍，大约9000行，具体以收到的拍数为准。

第0拍的起点与tick回调有先后差异，最初1～2拍可能因坐标/建议尚未就绪而降级；存在初期扣分风险，不能把零值当作真实目标位置。

## 6 结束、停车和保留结果

需要立即关闭运动时，在已加载环境终端：

```bash
ros2 param set --no-daemon /team43_tracking/visual_servo_node motion_enabled false
```

节拍结束后等待地图保存提示，确认正式目录有 `43.csv`、`43_map.pgm`、`43_map.yaml`，再在主终端 **Ctrl+C**。串口桥退出补发零速，真实电机制动仍以现场状态为准。

保留上午 `maps/`、下午本轮 `records/` 和正式输出。新一轮需要重新启动下午程序并重新定位；轮次清理由主办方流程决定，不自行删除提交文件。

## 7 参数覆盖和边界

- 另一个上午地图：`bash tools/start_match.bash map_yaml:=/绝对路径/43_slam_map.yaml`。
- 独立实验室实时建图调试：`bash tools/start_match.bash map_mode:=live`。这会从零建下午图，不会复用上午成果，不用于本次分时比赛默认流程。
- 只读检查：加 `motion_enabled:=false`。
- 其他装车/相机/串口配置仍用 `vehicle_config:=...`、`camera_config:=...`、`port:=...` 显式覆盖。

旧二维图用于一次初始重定位，下午移动由新LIO跟踪；本次没有给Small Point-LIO增加PCD地图加载、全局回环或持续旧图约束，因此长时间漂移仍可能存在。匹配质量通过不是实物精度验收。上午场地与下午固定结构变化过大时，需要现场核查旧图是否仍适用。
