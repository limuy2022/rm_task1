# 比赛启动与收尾

按裁判确认的顺序操作：**先运行程序 → 裁判告知目标ID → 设置目标并确认跟踪 → 裁判启动比赛客户端。** 相机由赛事方启动；本队入口启动雷达、串口桥、LIO、建图、感知、控制和提交。

## 1 先运行程序

确保NUC已编译当前代码；`team43_bringup/config/vehicle_field.yaml`已录入本轮机械尺寸和用户允许的代理近似，[对应关系见此记录](../记录/本轮装车配置与近似依据.md)。启动前保持底盘静止、相机水平朝车头，保持到日志提示首次参考对齐完成。入口优先读取根目录个人vehicle43.yaml，没有个人文件时自动读取随包安装的本轮配置。若NUC已有旧的个人文件，本轮启动时明确传`vehicle_config:="$PWD/src/team43_bringup/config/vehicle_field.yaml"`，不必再抄模板。正式目录为`~/ws_championship/src/43-MyDuo`。

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/start_match.bash
```

保持终端运行。默认`target_id=-1`，表示等待裁判通知目标；不会自行选一个码。默认`motion_enabled=true`、`continuous=true`，设置目标后自动跟踪。

入口直接启动全链，不等待人工confirmed开关、配置epoch匹配或源地图就绪，也不需要现场重新提交B4材料。它沿用文件中的安装数值，首次云台反馈自动绑定当前epoch；本轮配置以启动时水平朝前为参考，从首次同步姿态自动计算世界对齐旋转，不需手填B4数值。运行中发生设备复位仍会停止，不能继续使用复位前的反馈。

启动日志和参数保存在新建的`records/match_XXXXXXXX/`：日志在`ros_log/`，源图在`source_map/`，本次运行参数为`vehicle_runtime.yaml`。运行参数快照不是标定或验收通过证据。

串口打不开、驱动无法加载、配置文件缺失或数值非法仍会明确报错；这些是真实运行错误。不要同时运行第二份本队驱动、桥或控制器。

## 2 裁判通知后设置目标

另开终端，进入同一项目目录。假设裁判通知目标为ID 3：

```bash
cd ~/ws_championship/src/43-MyDuo
bash tools/set_target.bash 3
```

脚本会切换共享检测器和PnP，不重启雷达、桥、定位或提交器。它先暂停PnP处理，更新检测ID，再恢复PnP，避免切换期间把排队的旧目标当作新目标。两次参数读回应与裁判通知的ID一致。

检查相机画面中的指定码，并在已加载环境的终端看一次跟踪状态：

```bash
ros2 topic echo /team43_tracking/status --once
```

应看到对应`id`及“跟踪中”；`continuous`为true。缺图、缺IMU或缺关节反馈时会显示实际等待原因。默认自动运动，无需再手动开启motion_enabled。

目标在启动前已经知道时，也可直接用`bash tools/start_match.bash target_id:=3`。

## 3 确认完成后，由裁判启动比赛客户端

必须先让整条处理链接收底盘位姿，再通知裁判开始本轮。[校内赛环境说明](https://blog.secaumene.com/kit/campus-contest-env.html#比赛流程与评分程序的话题)已明确：赛题一第0拍同时发布`/judge/replay_start`，消息类型Header，QoS为transient_local，frame_id为record或replay；评分节点启动约3秒后开始10Hz发拍，赛题一持续180秒。

程序使用本轮有效replay_start的stamp确定正式起点，忽略启动前的旧锁存值，不用首拍或最新位置代替。两个话题的回调先后不保证：若tick先到，CSV仍立即写行，起点在replay_start到达后确定。地图按起点stamp查询真实底盘历史位姿；缺少覆盖该时刻的位姿时等待数据到达，不伪造原点。

提交器在第一拍才打开CSV：评分客户端启动时删除旧CSV不会让参赛程序退出。后续检测到路径被删除、替换或截空，会重新打开当前路径并写入当前拍，不恢复已被清理的旧行。开赛前CSV尚未出现属于正常情况。

正式输出为`~/ws_championship/output/43.csv`和`43_map.pgm/yaml`。本队不向`/judge/*`发布测试消息，不删除或截断已有提交；轮次文件按主办方流程准备。

```bash
wc -l "$HOME/ws_championship/output/43.csv"
```

开赛后行数应随节拍增加。同一处理进程只对应一轮，新的比赛轮次按主办方流程停止并重新运行程序。比赛开始后才启动程序，无法补回错过的起点位姿。

### 3.1 只读调试和参数覆盖

只读采样或标定时明确关闭运动：

```bash
bash tools/start_match.bash motion_enabled:=false
```

还可传`vehicle_config:=绝对路径`、`camera_config:=绝对路径`、`controller_params:=绝对路径`、`lio_config:=绝对路径`、`livox_config:=绝对路径`、`port:=实际串口`、`continuous:=false`。

### 3.2 本场直接采用斜装调平与高度近似，不要求点地面

LIO按已采静止重力方向`[-0.0321952086,-0.6955923471,0.7122368773]`统一调平输出位姿和点云。源建图根据同一LIO配置的`lidar_height_m=0.2325`与内部光心偏移自动计算`floor_z≈-0.184333m`，来源为`height_approximation`。无需点地面或手填floor_confirmed。

这是用户授权采用的安装高度近似，不是点选实测结果；原始驱动坐标和内部雷达↔IMU外参不变。地图会在有效点云/位姿到达后自然产生，不阻塞其他节点启动。

## 4 停止与收尾

运行中随时关闭运动：

```bash
ros2 param set --no-daemon /team43_tracking/visual_servo_node motion_enabled false
```

待本轮节拍结束，确认主终端有地图保存结果，正式目录有CSV及配套地图文件。最后在主终端Ctrl+C退出整条链；保留本轮records目录和实际输出，不在下一轮程序启动时自行清除旧提交。文件保存失败时根据实际日志处理，不把空地图文件当作成功。
