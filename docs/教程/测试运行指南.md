# 测试运行指南

本仓库的验证分层组织，全部在 **ROS 2 Humble 容器**（`Dockerfile`，与 NUC 同源环境）里运行；
本机不需要装 ROS/pytest。先给速查，再分层展开。

## VS Code 开发容器

开发容器的 `.devcontainer/devcontainer.json` 直接构建根 `Dockerfile` 的 `test`
目标，包含 `/opt/livox/install`，不再使用旧的独立开发镜像配置。
修改配置后执行 VS Code 的 **Dev Containers: Rebuild Container**；已运行的旧
容器不会随镜像更新自动获得依赖。新终端使用 `ROS Humble + Livox` 配置，自动
加载 ROS 与 Livox 环境，不修改 `.bashrc`。

仓库位于 `/workspace`，编译产物继续放 `/tmp`。容器内先确认：

```bash
ros2 pkg prefix livox_ros_driver2
# 应输出 /opt/livox/install/livox_ros_driver2
```

通过 `docker exec` 等方式打开的独立 shell 需先手动加载：

```bash
source /opt/ros/humble/setup.bash
source /opt/livox/install/setup.bash
```

### GitHub Actions 仿真回归

`.github/workflows/ci.yml` 在推送 `main`、PR 和手动触发时，除标准验证外，
并行运行四个独立集成作业。任何场景退出非零都会使对应作业失败；不会取消
其余场景，也不会将失败标成通过。

| 作业 | Dockerfile 目标 | 场景 |
|---|---|---|
| `navigation` | `test` | 无噪声与 1cm 测距噪声两个跨进程定位建图场景 |
| `submission` | `test` | 1800拍/180秒真实DDS提交，独立读者检查完整行可见延迟、九列评分及非对称地图 |
| `gazebo_lio` | `gazebo-sim` | Small Point-LIO 原始核心，16线，方形运动与真实地图保存 |
| `gazebo_vision` | `gazebo-sim` | 同一核心，16线，features 场景、3cm 观测下限，含延迟/断流/旧帧重放 |

Gazebo 使用无显卡软件渲染，请求倍率为 0.25，脚本墙钟超时 900 秒；运行步骤
最多 25 分钟，整个作业含构建最多 60 分钟。倍率调整只给渲染和消息处理留出
时间，不改变传感器仿真频率、故障窗口或验收误差门槛，不作为实时吞吐验证。
32线和真实传感器实时吞吐仍需单独运行，当前 CI 不代表它们通过。

Small Point-LIO源码以固定提交直接包含在普通ROS包中，算法核心不打补丁；
接口层负责固定外参、消息与回调审核。标准回归固定 `lio_room_regression.sdf`，
不使用人工编辑的 Blender 场景。旧算法、补丁和诊断工具已移除；版本与验证见
[迁移记录](../记录/SmallPointLIO迁移验证.md)。

接收审核使用 `input_audit.csv` 与独立源时间戳：覆盖率至少 99.9%、无倒序，
实收最大间隔不超过源端实际最大间隔加 1μs，源 IMU 间隔另限 10ms；审核缺失也失败。
启动 Gazebo 前先等待 Point-LIO 的雷达与 IMU 订阅被发现（最多 15 秒），
防止首批数据先于后端订阅到达；订阅未就绪或后端提前退出时直接失败。
接收审核同时记录源端与后端首尾时间戳，帮助区分启动漏收、运行丢样和收尾积压。
仿真副本启用 `imu_qos_reliable=true`，与桥接端协商可靠 IMU 传输，避免共享
CPU 上 best-effort 不可重传的丢样；实机默认仍为 false，雷达 QoS 不变。
雷达源序列保存在 `lidar_published_stamps.csv`，不将名义 10Hz 当作严格 100ms 截止。
扩大接收队列不放宽定位、地图、TF 新鲜度或故障恢复门槛，也不代表实机实时吞吐通过。
收尾先调用 Gazebo 停止服务并保存 `gazebo_stop.log`；强杀或非零退出仍使验收失败。

CI 与本地共用 `tools/run_simulation_ci.sh`。例如复现视觉任务：

```bash
docker build --target gazebo-sim -t rm-task1-simulation .
docker run --rm -v "$PWD":/workspace -w /workspace \
  --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -e ROS_DOMAIN_ID=94 -e ROS_LOCALHOST_ONLY=1 \
  -e IGN_PARTITION=rm_task1_ci_gazebo_vision -e LIBGL_ALWAYS_SOFTWARE=1 \
  rm-task1-simulation bash tools/run_simulation_ci.sh gazebo_vision
```

其他任务替换末尾场景名及 `IGN_PARTITION`；`navigation`、`submission` 构建时改用 `--target test`。
入口会构建工作区，产物仍全部放在容器 `/tmp`，不会重复安装 ROS 依赖。
Gazebo 场景由 `team43_gazebo` 安装，入口在 source 工作区后选择包内标准房间；
模型搜索路径由包的环境 hook 配置，C++ 插件仍只在 `gazebo-sim` 镜像中编译。
日志、`result.json`、PNG、CSV 和地图保存在
`build/offline/ci_simulation/<场景>/`，即使场景失败也上传名为
`simulation-<场景>` 的 artifact，保留 7 天。镜像构建失败时尚无仿真产物，
应查看 Actions 构建日志。默认不录 bag，避免上传大量图像和点云。
本地重跑前先移走对应输出目录，入口拒绝覆盖旧证据。

## 1. 环境准备

首次克隆后先检出子模块，否则一致性检查会失败：

```bash
git submodule update --init --recursive
```

```bash
docker build -t rm-task1-humble-test .
```

两种用法：

**一次性执行**：构建镜像后直接使用第 2 节的完整命令。

**交互式**（适合反复跑单个测试、调试）：

```bash
docker run -it --rm -v "$PWD":/workspace -w /workspace \
  --user "$(id -u):$(id -g)" -e HOME=/tmp rm-task1-humble-test bash
# 进入后：
source /opt/ros/humble/setup.bash
colcon --log-base /tmp/clog build --build-base /tmp/cb \
       --install-base /tmp/ci --symlink-install
source /tmp/ci/setup.bash
```

⚠ 两个注意：
- 每次 `docker run` 都是**全新容器**，`/tmp` 里的构建产物不跨容器留存——一次性执行时命令里要自带 build。
- 仓库挂载在 `/workspace`（ASCII 路径），容器内对仓库的修改会直接落回宿主目录。

## 2. 标准全量验证（一条命令）

先按第 1 节构建镜像，再执行以下命令；执行步骤与 Dockerfile 头注释及 CI 一致：

```bash
docker run --rm -v "$PWD":/workspace -w /workspace \
  --user "$(id -u):$(id -g)" -e HOME=/tmp rm-task1-humble-test bash -c '
    source /opt/ros/humble/setup.bash &&
    colcon --log-base /tmp/clog build --build-base /tmp/cb \
           --install-base /tmp/ci --symlink-install &&
    source /tmp/ci/setup.bash &&
    colcon --log-base /tmp/clog test --build-base /tmp/cb \
           --install-base /tmp/ci --packages-select team43_serial_bridge &&
    colcon --log-base /tmp/clog test-result --test-result-base /tmp/cb --verbose &&
    python3 -B -m pytest -q src --import-mode=importlib &&
    python3 -B tools/verify_all_offline.py --skip-pytest'
```

覆盖四层：colcon 构建 → C++ gtest → 全部 pytest → 全部离线核验脚本。

### 4.1 pytest 文件

测试统一收集 `src/*/test/test_*.py`。模块测试、跨模块集成与 launch 检查的分工见第 3 节；
完整清单以源码为准，不在教程维护逐文件用例数。工具职责索引见[工具入口](../../tools/README.md)。

维护测试时优先验证可观察行为，避免用源码中出现函数名、话题字符串来证明功能存在。
启动顺序与光学旋转的 launch 一致性统一由 `test_launch_sim.py` 验证；
真值订阅接线由 `test_node_itest.py` 验证，静态检查继续限制真值话题不得泄漏到业务包。
配置路径检查从无关工作目录读取已安装包的默认配置；统一时钟检查注入不同的单调时钟读数，
防止误用墙上时钟或固定值也通过。协议列序、坐标符号和停转约束即使断言很短，也应保留。

单独运行示例（在已构建并 source 工作区的容器中）：

```bash

python3 -B -m pytest -q src/team43_control/test/test_image_error.py::test_sign_conventions --import-mode=importlib -v
```

### 4.2 工具脚本（tools/）

**`tools/aim_sim.py`** —— 可退化合成图像渲染器（库，非测试）。真畸变投影（team43 内参）
+ 传感器噪声 / 方向性运动模糊 / 离焦 / 边侵入式遮挡 / 曝光摆动 / 纹理背景，
全部 `np.random.default_rng(seed)` 确定性。核心接口：

```python
from aim_sim import render_scene, tilted_rvec
image, gt_corners = render_scene(camera, marker_id=3, tvec=(0,0,2.0),
    rng=np.random.default_rng(0),
    noise_sigma_px=6.0, motion_blur_px=9.0, blur_dir_deg=25.0,
    defocus_px=1.8, occlusion_frac=0.18, gain=0.8, bias=-15.0,
    background='texture')
# ⚠ 斜置姿态必须用 tilted_rvec(droll,dpitch,dyaw)——直接给小角度 rvec
# 会替换正立基准，得到 180° 翻转的码（解出不同 ID）。
```

**`tools/verify_aiming_robustness.py`** —— 瞄准链退化回归。三层断言：
静态检测命中率 + PnP 位置误差界（9 档退化 × 4 姿态）、闭环收敛
（真检测器 → 生产图像 PID → 理想速度植物）、丢失语义（遮挡突发恢复、
持续丢失停转不 fault）。
当前快速档每档为4姿态×3帧，全量为4姿态×12帧；非遮挡档同时要求PnP有效率
至少95%，每帧误差按其真实距离检查。闭环最后15帧至少14帧有新观测，且误差
均小于8px。遮挡停止必须实际发送三零帧并静默，不能以空列表判成功。
这些样本数用于确定性回归，不构成真实场景99%命中率的统计置信保证。

```bash
python3 -B tools/verify_aiming_robustness.py --quick   # 快速档（verify_all 用）
python3 -B tools/verify_aiming_robustness.py           # 全量：静态48样本/档，闭环150帧/档
```

结果 JSON 打印并存 `build/offline/aiming_robustness.json`；失败列明场景与原因。

**`tools/score_bearing_sim.py`** —— bearing_sim 闭环产物（`final.json` + `final.csv`）
离线评判：RMS 与 evaluator 互检、settle 后超调比、振荡率（次/分钟）、
平滑度（°/s）、丢样检测（时间戳间隙）。

```bash
python3 -B tools/score_bearing_sim.py build/bearing_sim_final
python3 -B tools/score_bearing_sim.py build/bearing_sim_final \
    --max-overshoot-ratio 5 --max-osc-per-min 40 --max-gap-s 0.2   # 带阈值判 FAIL
```

### 4.3 独立核验与验收条件

`verify_all_offline.py` 当前编排 19 项独立核验，默认先运行 pytest；标准全量流程
已经单独运行 pytest，因此使用 `--skip-pytest`。具体作业清单与超时以脚本为准。
launch 冒烟检查在已配置 ROS 环境中遇到安装缺失必须失败。

`verify_visual_tracking_dds.py` 使用真实 `visual_tracking.launch.py`、独立 ROS 域及 PTY，
覆盖默认静默、显式开启虚拟运动、图像/PnP/两轴指令、断图三零帧及静默、
恢复、参数关闭与运动中 SIGINT 正常退出。软件退出顺序不保证真实电机的制动时间。

`verify_visual_tracking_pipeline.py`在理想基线外，增加67ms命令延迟、80ms一阶响应、
0.001rad/s死区和限幅的阶跃/移动目标场景，保持生产增益，检查最后1秒最大指向误差
分别小于0.4°/0.9°。这是合成执行器回归门槛，不能代替实测动力学。

180秒合成算法流水线同时要求总误差分数≤0.04（越小越好）、目标有效率≥99%、
最长连续失效≤6拍、正常窗口无失效、遮挡确实触发失效且恢复不晚于第612拍。
误差诊断排除的预热/遮挡窗口仍参与总评分和有效率，结果写入`pipeline/result.json`。

`verify_submission_dds.py`复用`submission_test_source.py`及`observe_submission.py`，
实际启动`submission.launch.py`并把节拍/回放映射到`/test/*`；默认30拍作快速回归。
CI独立`submission`作业运行1800拍，要求独立读者在写出节点仍运行时看到全部完整行，
每行可见延迟<60ms，节拍跨度符合10Hz、最大间隔<200ms，并校验评分、PGM像素及YAML。
产物为`submission_dds/`，可用`--output-dir`指定；失败也保留日志和`result.json`。
容器主机的可见延迟不代表NUC通过，也没有验证独立实测标定或MID360真实误差。
退出验收包括测试源和评分节点正常结束，无回调内 shutdown 死锁或重复关闭异常。

作业超时由 `tools/verify_all_offline.py` 的 `timeouts` 字典维护；失败或超时均保存日志，继续运行其他作业。

## 6. 换相机标定对测试的影响

实测结论（用他队参考标定 fx 998.7、以及 newost 的 K/D 与 P 当 K 两个变体验证）：

1. **自洽型测试不敏感**：PnP 往返、感知离线核验、image_error 网格/PnP 互检等
