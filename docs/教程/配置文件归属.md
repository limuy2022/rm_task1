# 配置文件归属与加载顺序

只被一个功能包使用的跟踪链参数，存放在该包的 `config/tracker_defaults.yaml`：

| 包 | 参数 |
|---|---|
| team43_gimbal_io | `serial.*` 及本包云台故障参数，Python 虚拟串口桥 |
| team43_control | `control.*` 与 `gimbal.limit_margin`，world/轴承闭环 |
| team43_perception | `perception.*`，检测与 PnP |
| team43_estimation | `estimation.*`，目标估计 |
| team43_localization | `localization.*`，底盘定位与地图原点 |
| team43_chassis_advisor | `chassis.*`，底盘速度建议 |
| team43_grid_mapper | `grid.*`，栅格地图 |
| team43_judge_io | `judge.*`，评分输出 |
| team43_debug | `debug.*`，仿真评估 |

表内命名空间有共享例外：`perception.r_min_sigma` 同时被感知与估计使用，
`localization.world_odom_xyz_rpy` 同时被定位与控制使用；它们仍存放在
`team43_bringup/config/tracker_params.yaml`。该文件还保留跨包云台限位、
底盘到云台安装外参、CSV 目录与轮次、任务时长、调试启动开关、配置路径和时钟设置。
`team43_dataio` 目前没有独占的 YAML 参数，因此不新建空配置。

两个单节点配置也已迁移：

- 图像控制器：`team43_control/config/visual_tracking.yaml`。
- 点云建图：`team43_grid_mapper/config/cloud_mapping.yaml`。

C++ 串口桥的 `team43_serial_bridge/config/bridge.yaml` 和 Point-LIO 的
`team43_lio_backend/config/small_point_lio_mid360.yaml` 继续留在原包。
Python 串口桥与 C++ 串口桥是不同实现，不能互换它们的参数文件。

bringup 保留整车集成相关配置：相机内外参、场地、整车实测模板、台架和仿真场景。
同一项标定数据只维护一份，不复制到各算法包。

## 启动时怎样组合

原先读取 tracker 全表的启动入口，改为依次加载：

1. 节点所属包的 `config/tracker_defaults.yaml`。
2. bringup 的 `tracker_params.yaml` 共享配置。
3. 整车/台架/仿真场景文件（若入口有使用）。
4. 启动文件生成的显式参数覆盖。

后面的同名键覆盖前面的值。原有 `params_file`、`vehicle_config`、
`controller_params` 参数继续可用，自定义旧全表文件也可作为覆盖文件加载。
只修改目录归属，原表各参数的名称、类型与数值不变。

`processing.launch.py` 原先只读取实测整车文件，仍保持该方式，避免引入原先未使用的
跟踪链默认值。`submission.launch.py` 等独立入口也保留既有参数行为。
`visual_tracking.launch.py` 的 `controller_params` 默认路径现在指向控制包；
`cloud_mapping.launch.py` 的 `params_file` 默认路径现在指向建图包。
如个人脚本写死了这两个旧路径，需相应更新。

功能包的配置通过各包 `setup.py` 安装到 `share/<包名>/config/`，启动时由 ament
索引定位，不依赖工作目录。新增文件或修改安装规则后须重新构建相应包，再 source 安装空间；
已有 install 中的旧副本不能作为新文件已安装的证据。运动开关保持默认关闭，
实际运动仍按对应教程由人在参数终端显式开启。

## YAML 读取与 ROS 2 参数加载的边界

节点参数文件通过 `Node(parameters=[文件路径, 覆盖字典])` 交给 ROS 2 加载，
节点用参数声明与读取接口取值；ROS 2 不会自动扫描包内 YAML，也不会继续打开
`camera_config` 等字符串参数指向的文件。

相机、场地等普通业务 YAML 统一通过 `team43_common.config_loader.load_yaml()`
读取。默认允许空文档并返回空字典；要求文档必须是映射的调用使用
`allow_empty=False`。必需文件缺失、非法顶层类型均抛 `ConfigError`。

launch 在创建节点、生成静态 TF 或定时退出动作之前需要读取配置时，可以手动读取。
项目约定的 `/**: ros__parameters:` 结构统一通过 `load_ros_params()` 提取，
缺失或非法结构直接终止启动；该函数只服务于启动前决策与整车校验，
不模拟 ROS 2 的节点匹配、命名空间或参数覆盖规则。整车实测确认、固定雷达外参、
静态 TF 向量等业务校验仍在各自入口执行。YAML 语法错误保留 PyYAML 异常。

## launch 公共工具

启动入口共用的 share/config/RViz 路径定位与严格布尔解析集中在
`team43_bringup.launch_utils`，由 Python 包随构建安装；不要在各个
`*.launch.py` 中复制这些工具函数。路径定位不额外检查文件存在性；
功能包配置的存在性检查继续使用 `parameter_files.package_config()`。
各入口的节点编排、覆盖参数解析和业务校验仍留在对应 launch 文件中。
`bearing_sim` 保留原有的宽松布尔解析规则。
