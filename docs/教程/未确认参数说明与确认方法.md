外参包含旋转与平移。对某一固定变换，若旋转正确，仅省略长度为d的平移，单次点坐标误差的模就是d；多段偏移会组合，杆臂影响还会随姿态变化。旋转误差则按目标距离放大：小角度时横向误差约为D×角度误差（弧度）。例如3m处1°约5.2cm、5°约26cm。因此“相机和IMU挨得近”可以支持小平移近似，不能支持随意令旋转或IMU/LIO世界对齐为零。采用近似时记录依据、误差估计及验证结果，不将未知占位值改名为实测值；现有确认门禁本次不修改。

### 2.2 先查共同时间轴，再研究传感器延迟

如果已有证据显示时间轴异常，再针对性核对实际终端和节点设置，不作为每轮例行查询：

```bash
printenv ROS_DOMAIN_ID ROS_LOCALHOST_ONLY RMW_IMPLEMENTATION
ros2 param get /red_standard_robot1/team43_small_point_lio use_sim_time
ros2 param get /team43_tracking/visual_servo_node use_sim_time
```

未设置的环境变量可能没有输出，记录“未设置”并向现场接口负责人核对实际域与通信拓扑；变量相同也不能代替端点可见与实际收样。节点尚未启动时不执行对应param get。

首次联调时先让本队跟踪只看不动、LIO正常接收，在同一现场 ROS 域运行附录 A 15 秒。它记录图像角点、两份 IMU、自有位姿和允许订阅到的评分 Header，不保存原始图像或整帧点云。目标需在视野内；无效角点不用于图像时间统计。

1. 观察 `headers.csv` 中 `receipt_ros_s - stamp_s`。持续巨大偏差、时间倒退、明显未来时间，应先查单位、时钟源、主机同步和回放设置；先不调滤波器。
2. 各行是各消息的接收时刻。**不能拿两行到达时间差当传感器真实时延**；不同频率、DDS排队和调度都会改变它。
3. 角点的 stamp 是原图时间，但接收位置在检测之后，因此该列包含相机、传输、检测和采样脚本调度延迟；它不是纯曝光时延。
4. 同一时间原点不等于采样同步。需要时，在已完成外参的固定目标实验中，让主办方/现场人员做可重复、低速的小幅运动，录自有 LIO 位姿和云台 IMU的共同时间窗口；对齐可观测的同一物理转动，比较多个窗口的相位关系。坐标变换后再比较，不能将不同轴的 gyro 直接相减。
5. 静止窗口可用于世界旋转对齐，**不能据此估出动态延迟**。相机延迟更难，需已知运动和独立姿态/时间参考；缺参考时明确记“尚未标定”。

**判定与处理**：先证明各时间源可比较、单调且满足现有代码的新鲜度/插值条件，再评价运动中目标坐标误差。没有一个通用的“误差小于X毫秒就全部通过”标准。当前实机链没有统一的可配置时间偏移补偿，不能编造 `camera_imu_stamp_offset` 参数；确有稳定时延证据后再在相应数据接入层实现，并保留原始时间与校正依据。不要把超时扩大到任意值来掩盖不同时间原点。

**保存**：每个源的时钟来源、接收年龄分布、倒序/缺样本、动态实验窗口、估计偏差及不确定性。驱动、同步方式、负载或采集链变化后复核，不每次开机重新标定时延。

## 3 雷达原始坐标、设备型号与内部外参

### 3.1 量的定义

本队接收层使用：

```text
p_IMU = extrinsic_R × p_LiDAR + extrinsic_T
```

| 参数 | 当前值 | 意义与单位 |
|---|---|---|
| `extrinsic_T` | `[-0.011,-0.02329,0.04412]` | 雷达坐标原点在 IMU 坐标中的位置，m |
| `extrinsic_R` | 单位矩阵，9个数按行排列 | 把雷达轴表达的向量转到 IMU 轴；不是 rpy |
| `extrinsic_est_en` | false | 本项目仅使用固定外参，不接入在线估计结果 |
| `world_frame/body_frame` | lio_world/body | 本队输出的世界系名称与 IMU参考系名称，改名字不会完成实物坐标转换 |

这些值在 [LIO 配置](../../src/team43_lio_backend/config/small_point_lio_mid360.yaml)中。2026-10-31用户已确认输入点云未经过驱动坐标变换，使用厂家原始雷达系；此项不再待查。[校内赛环境页](https://blog.secaumene.com/kit/campus-contest-env.html)已明确型号为MID360，不再作为待确认项；厂家原点/轴定义及内部R/t仍需对应资料，不能由“未变换”推导出R/t为零。

### 3.2 怎样确认与填写

1. 型号直接记录MID360，来源为校内赛环境页；保存安装方向照片和本队实际启动配置，不重复要求查铭牌。
2. 使用厂家该型号的坐标图和内部 IMU—雷达外参说明，明确两个原点、各轴方向、变换方向与单位。设备内部尺寸优先采用可信厂家依据，不用外壳边缘的尺量替代内部 IMU 原点。
3. 沿用已确认的原始雷达坐标输入，按上式应用厂家对应的固定R/t；驱动无需改动，本队接收层负责转换到IMU。当前默认值仅在型号、原点/轴与资料匹配时采用，不因两者在同一设备内就清零外参。
4. 需要验收定位效果时，再用静止、已知距离平移、慢转及返回标记点观察墙面重影/位姿漂移。此实验验证整体效果，不能仅凭“墙看起来直”唯一反解出内部外参。

**判断标准**：输入未变换已确认；MID360型号已有环境页依据；原点/轴、公式方向、具体R/t需有来源，定位和cloud_mapping使用同一份LIO配置。R应正交、行列式约为+1，这只证明数学合法，不证明数值对应实物。

若以后驱动改为输出IMU/车体系点云，需重新处理输入变换，同时保留建图所需的物理雷达原点，不能将两项一起清零；当前不走该适配分支。

**写入/重启**：写自己的 LIO 配置副本，停止并重启 LIO 与源建图；LIO 会话改变后更新世界对齐和地面。定位接收层将点统一到 IMU，算法核心使用 identity；不要再在核心/建图中复制一次同样的变换。

### 4.2 一次正式环境联调怎样确认

复用已确认的评分话题和通信设置，不再运行端点/类型发现步骤。校内赛环境已明确提供起点和节拍。程序忽略启动前的旧锁存起点；处理链须在客户端开赛发拍前就绪。

B 在客户端开始发拍之前启动处理链，使底盘历史覆盖所选起点时刻。本轮replay_start到来后，日志应报告按其stamp冻结原点；CSV开始随tick增长，输入状态应有效。拿到 replay_start 并不等于起点已冻结；若缺历史位姿，不能拿最新位置补成起点。

若话题名不同，可用已核对的 ROS remap；独立 `submission.launch.py` 也有 `tick_topic/replay_topic` 参数。**`processing.launch.py` 没有这两个专用 launch 参数**，不能将它们直接追加后以为已生效。类型或时间含义不同须先确认接口并适配；tick的QoS不匹配时联系接口负责人；若起点尚未收到，CSV仍逐tick写行，但比赛坐标等待本轮replay_start，按环境约定订阅其transient_local消息。

写盘及时性和180秒连续性另按[评分接口测试](评分接口测试.md)在隔离域、新目录验收。通过合成演练只能证明本队消息/写盘链；正式端点证据须来自真实接口。实机正式运行须采用同一部署版本，保留实际结果与收尾采集日志。

## 5 电机指令方向、速度与停止行为

### 5.1 参数不是同一层的符号

| 参数/量                          | 当前值                      | 改什么                                      |
| ----------------------------- | ------------------------ | ---------------------------------------- |
| 图像控制器 `yaw_sign/pitch_sign`   | 1.0/1.0                  | 对应轴输出指令的符号，可在线修改并保存                      |
| C++桥 `yaw_sign/pitch_sign`    | visual_tracking 启动时固定1/1 | 桥转发角速度的符号；同名但不是同一节点的参数                   |
| 桥 `imu_axis_sign`             | `[1,1,1]`                | 仅作用于反馈accel/gyro，不改q；沿用record4，不拿它修正电机方向 |
| Twist 的 `angular.z/angular.y` | yaw/pitch，rad/s          | 转发到0x30；不是度/秒，也不是直接拿gz当机械yaw角速度          |
| `max_omega/slew`              | 默认0.25rad/s、1.0rad/s²    | 每轴速度和速度变化上限；第一轮方向试验用教程中的0.08rad/s        |

record4本身的反馈与手动动作不能证明0x30指令执行正确；用户后续报告的持续瞄准，则确认了现场所用执行链的功能。若该链使用本仓库的串口桥，可将其实际用到的命令路径视为已打通；若启动程序不同，结论只归于现场那套程序。当前两层指令符号相乘，修改一层即可；不要两层同时翻转、结果相互抵消。

### 5.2 确认方法与判据

同一现用链路中，若已经观察到yaw、pitch分别把实际图像偏差纠正回去，相应轴的组合指令符号已得到功能验证，不重复基础方向试验，也不为填表重新翻转sign。仅对未覆盖的轴，或首次更换控制程序/机构/符号配置后，按[云台跟踪第4节](云台跟踪.md#4-切换到能转动的模式)补做对应低速试验。沿用唯一串口桥；运动默认false，A摆码、B在参数终端操作，C观察电线和机械余量并负责现场停机。不要另发手写串口帧或直接发布速度绕过现有门控。

持续瞄准说明已试场景中的控制参数足以工作，先保存现用参数，常规PID调参可暂缓。仅保持静止码居中不能证明两轴动态纠偏；只测过某个方向、距离、速度或角度，也不扩展为全部范围通过。独立图像PID使用角点中心与相机模型，不使用PnP距离、雷达、底盘TF或整车外参，因此持续瞄准不能确认三维位置精度、LIO与世界对齐。成功跟踪期间没有触发异常，也不证明遮码/反馈中断/复位及停机行为已实测。

1. 先读status，再人工开启单轴；画面偏差必须向0减小。像素右侧目标对应默认负yaw、下侧对应默认正pitch，但最终判据是实际相机转向目标。
2. 反向立即关闭运动，仅在控制器对应sign上改正，再做同样小幅实验；不改已有IMU轴参数。
3. 有指令却不转时先看桥日志、命令与实际响应，不判定一定是PID增益问题。保留固件/板卡版本、启动命令与现象。
4. 在已知姿态附近，短时小幅记录角度随时间变化，评价实际速度量级；斜率限速、启动过渡和闭环误差都会使实际速度与瞬时请求不同。不是看到一个非零Twist就完成速度验收。
5. 实际验证 `motion_enabled=false`、启动终端Ctrl+C、遮码、反馈中断/复位锁停的行为；有些故障实验应在低速台架进行，不在正式比赛临时拔线。

停止命令：

```bash
ros2 param set /team43_tracking/visual_servo_node motion_enabled false
```

代码会请求零速度并停止发送；固件约定的减速/失能时间不代替实测制动时间。结果写入现场记录，控制器参数按[调参清单第3节](上机调参检查清单.md#3-调好了怎么保存下次怎样恢复)导出；相同配置不每轮重做全套试转。

## 6 TF发布归属与坐标链

这里确认的是**哪一个程序负责发布哪条边**，不是再测一次安装尺寸。

| 当前期望TF边                                      | 本队发布者                      | 什么时候应存在                                    |
| -------------------------------------------- | -------------------------- | ------------------------------------------ |
| map→odom                                     | map_frame_broadcaster_node | 正式起点历史覆盖并冻结后                               |
| odom→lio_world                             | team43_odom_source_parent  | processing使用模板的源父系lio_world时；由约定的源父系变换生成 |
| odom→base_link                               | base_pose_provider_node    | 有有效自有LIO位姿且底盘外参已确认                         |
| base_link→gimbal_link                        | gimbal_kinematics_node     | 基座位姿、云台IMU、外参与epoch全部有效                    |
| gimbal_link→camera_link→camera_optical_frame | gimbal_kinematics_node     | 首次得到有效运动学结果后发布静态安装边                        |

Small Point-LIO输出 `lio_world/body` Odometry，**本队backend不因此自动发布 lio_world→body TF**，不要把找不到这条TF误判为没有定位。visual_tracking中的串口桥应为 `publish_tf=false`，不同时再发布 `world→gimbal_link`。

### 确认方法

先按附录 A 同时采集 `/tf`、`/tf_static` 的父子边，并保存发布节点清单。**该Humble Python采样器没有每条TF消息的发布者GID，不能把边和节点直接一一配对**；graph.json中的GID只是端点信息。

1. 对照上表、源码/launch和 `ros2 node info`，列出本队每条边的预期发布者与实际运行节点。
2. 同一TF话题有多个发布节点是正常现象；要确认的是每条边的归属，不能只要求 `/tf` 的publisher count等于1。
3. 如果归属仍有歧义，在非比赛联调窗口，只对本队可控的候选程序逐一停止并重新采样，比较动态边是否停止更新。静态TF可能仍留在旧监听器缓存中，需新建采样订阅者查看仍存活发布者的锁存数据，不能看旧RViz缓存猜结论。
4. 对外部程序由现场负责人确认其发布边，不自行停止。仍不能归属时明确记录未确认；需要直接逐消息区分来源时，应另用Humble C++ MessageInfo诊断工具，不能声称本附录已经证明唯一发布。

订阅开始晚、采样窗短或节点未就绪会漏边；“没采到”不能单独证明不存在。

```bash
ros2 node info /gimbal_kinematics_node
ros2 node info /base_pose_provider_node
ros2 run tf2_ros tf2_echo odom camera_optical_frame
```

正式起点之后再查：

```bash
ros2 run tf2_ros tf2_echo map camera_optical_frame
```

连续输出用Ctrl+C停止。`tf2_echo`证明可查询到一条链，不能单独证明没有重复发布者。多个节点发布同一条边，即使数值暂时相同，也须明确保留谁；同一个child出现不同parent须处理。本队可停自己的重复入口；外部节点由现场负责人协调，不通过全局pkill解决。

归属实验中如果重启了桥或LIO，会使epoch或坐标关联失效，按第7节重新建立受影响的关系。

**保存**：父/子、静态或动态、发布节点与归属依据、变换来源、适用会话。TF拓扑或节点编排变化后复核；硬件/程序不变时不每轮重新画树。

## 7 整车外参、机械零位、世界对齐和确认标志

### 7.1 统一约定和各参数的物理含义

`T_A←B` 把B中的点转成A中的点：`p_A = R_A←B p_B + t_A←B`。xyz单位m，rpy顺序roll/pitch/yaw、单位rad，使用 `Rz(yaw)Ry(pitch)Rx(roll)`。平移是**B原点在A轴上的分量**，不能量一条斜距当三个分量。

| 参数 | 对应关系与含义 | 怎样确定 |
|---|---|---|
| `localization.sensor_in_base_xyz/rpy` | `T_base←body`；LIO的IMU参考点相对底盘中心，不是雷达玻璃罩的位置 | 依据传感器原点定义和底盘中心基准，量三分量并确定轴向；用已知转动/杆臂实验验证 |
| `localization.source_parent_in_output_xyz/rpy` | `T_odom←lio_world`，两套世界坐标的约定 | 若按定义选同轴同原点，可采用identity；这是坐标定义，不要求量一只新传感器 |
| `kinematics.base_mount_xyz/rpy` | `T_base←yaw安装基准` | 最终装车后从底盘中心量到可复现的yaw轴基准；旋转依据机械基准 |
| `kinematics.yaw_to_pitch_xyz` | yaw转后坐标中，yaw基准到pitch轴基准的偏移 | 记录所处关节姿态，用yaw转后轴分解三方向距离 |
| `kinematics.pitch_gimbal_xyz/rpy` | pitch转后坐标到G参考原点与轴 | 固定G建模原点，记录其相对IMU/转轴关系，再量固定边；与下一行使用同一G |
| `kinematics.gimbal_camera_xyz/rpy` | `T_G←camera_link`，相机安装关系 | 确定光心/代理点及图像上方向，再量平移、确定相对旋转；不是相机光学O/C转换 |
| `kinematics.joint_zero_rad` | `[yaw,pitch]`；报告机械关节角为0时，模型轴角的固定偏移 | 用可重复机械标记/可信编码器依据定义零位；不能拿本次IMU世界yaw直接充当机械零位 |
| `kinematics.odom_world_rpy` | `R_odom←云台IMU惯性world` | 同一静止窗口结合已知机械姿态计算，见7.3；不是底盘安装尺寸 |
| `kinematics.calibrated_epoch` | 本次对齐对应的桥/MCU会话整数 | 对齐时读取并原样保存，不能沿用重启前的数值 |

这些参数的完整链及实物测量方法见[坐标外参第2～5节](坐标外参与整车接入.md)。首轮每段保留有依据的粗测值、基准照片、估计误差与关节姿态；需提高精度时再重复尺量或标定，相机代理点未知偏移单列。不能因为程序接受数学合法的全零矩阵就把它当实测成功。

### 7.2 零位与角度的易混点

代码使用 `模型轴角 = 报告关节角 + joint_zero_rad`。因此 joint_zero_rad 的数值取决于**你如何定义机械零位及模型固定边**，不是随手把当前q的yaw/pitch抄进去。若根据可信机械定义把零姿态轴角也定义成0，这个零值可以成立，但必须有定义和验证依据。

在至少两个已知关节姿态上验证反解与实物一致，单一姿态可以隐藏固定偏差。只看重力可约束倾斜，不能单独确定绝对yaw。无法重复找到零位就保持 `joint_zero_known=false`，不在软件中猜一个角度。

### 7.3 本次上电世界对齐

1. 先有最终安装尺寸与已知机械姿态；否则缺少解算依据。
2. 保持装置静止，按[坐标接入第7节](坐标外参与整车接入.md#7-b-录同步数据再启动处理链)同步录LIO位姿、云台IMU和epoch约5～10秒，A/C记录真实姿态。
3. 用底盘中心位姿与已知机械关节，计算同一时刻 `R_odom←G = R_odom←base R_base←G`。
4. 从同一窗口取得 `R_world←G`，计算 `R_odom←world = R_odom←G (R_world←G)ᵀ`，再转换为规定顺序的rpy。
5. 在另一个已知姿态核验；将结果和本次epoch一起保存。若这一期间桥/MCU复位或LIO重启，重新建立受影响的对齐关系。

读epoch命令：

```bash
ros2 topic echo /task1/gimbal_reset_epoch --once --qos-reliability reliable --qos-durability transient_local
```

只更新epoch数字不会自动重新标定旋转。只有桥进程变化、且另有充分证据证明IMU惯性参考和LIO关系未变时，才能依据该证据决定是否可复用旋转；不能仅凭“云台没动”认定可复用。

### 7.4 确认标志究竟确认什么

| 标志 | 何时才能为true |
|---|---|
| `localization.sensor_extrinsics_confirmed` | IMU body到底盘中心的R/t已确定并有依据 |
| `localization.parent_transform_confirmed` | lio_world到odom的定义及变换已明确 |
| `kinematics.mounted_on_base_confirmed` | 最终装车刚性关系成立，测量基准与运行模型一致 |
| `kinematics.joint_zero_known` | 零位有可重复依据，不能由IMU任意初始yaw代替 |
| `kinematics.calibration_confirmed` | 本节固定几何、零位、世界对齐与限位完整且可验证 |
| `estimation.geometry_confirmed` | 相机到比赛坐标的几何链已具备独立位置验证依据 |

false不是待填写的装饰：`processing.launch.py` 会拒绝未确认配置。完成并保存证据后才改为true；单独改true不会生成真实外参。

## 8 机械限位、试转保险丝和可跟踪范围

**本轮记录**：左右各约80°，相对水平前视上仰45°、下俯60°；已作为用户授权近似范围写入vehicle_field.yaml，控制器另留内侧余量。这不是寻找机械硬端的结果；更高可靠性复核仍按[B3](#b3-参考零位和工作范围先建立能重复找到的姿态)进行。

| 参数 | 用途/确认方法 |
|---|---|
| `kinematics.yaw_limits_rad` / `pitch_limits_rad` | 实测相对底盘的允许工作区间，同时用于运动学反解和比赛控制保护；模板值不是测量结果 |
| `kinematics.joint_limits_confirmed` | 仅在区间相对零位定义清楚且已验证时设true；match入口要求明确确认 |
| 控制器`operating_mode=match` | 一键比赛入口强制使用；读取当前epoch下的新鲜`/gimbal/joint_states`；相对底盘关节角越界锁停，边缘阻挡朝外速度、允许向内恢复 |
| `joint_limit_margin_rad` | 比赛控制默认0.035rad（约2°）软件余量；不是机械停止距离，实物停止余转仍需测量 |
| 控制器`operating_mode=bench` | 独立台架默认，保留`max_rotation=0.35rad`约20°世界姿态预算及`run_seconds=15`试转预算；continuous仅取消时间预算 |

比赛模式不再把世界IMU姿态变化当成关节行程，底盘转动不会仅因累计世界转角超过20°触发台架保险丝。它仍需要新鲜图像、云台IMU、有效关节反馈和与标定一致的epoch；不能绕过装车几何。按[实验室统一验证第6节](实验室统一验证.md#6-实物跟踪范围软边界和停止)测所需大角度、长时跟踪和实物停转。

反解仍要求yaw区间宽度小于2π；pitch加零位后的有效区间在(-π/2,π/2)内。这是模型可辨识限制，不能填假限位消除错误。安装不变时区间可复用，世界对齐须对应本次会话。

## 10 IMU量程和饱和阈值

| 参数 | 当前值 | 含义 |
|---|---|---|
| `acc_norm` | 1.0 | 静止重力在输入加速度单位中的大小；核心按 `9.81/acc_norm` 换为SI量级 |
| `satu_acc` | 3.0 | 输入加速度各轴的饱和判定幅值，单位与原始输入加速度相同，当前是g量级 |
| `satu_gyro` | 35.0 | 输入角速度各轴饱和判定幅值，当前按rad/s使用 |
| `check_satu` | true | 是否将达到饱和的相关IMU观测分量排除更新 |
| `gravity` | [0,0,-9.81]m/s² | 算法世界系的重力向量；不能把它改成[0,0,-1]来适配g输入 |
| `fix_gravity_direction` | true | 初始化时利用静止IMU建立重力方向，需要提供足够的有效静止样本 |

record3 的0.99289已足以支持当前g输入配置，本页不安排再量一次“1还是9.81”。**静止均值不能证明设备最大量程是±3g**，也不能证明角速度量程或rad/s换算系数正确。

确认设备型号、驱动对原始数值的缩放以及厂家/驱动实际配置的满量程；只使用现场负责人提供的非保护资料。附录A保留的IMU六轴样本可用于观察正常动作范围和是否异常削顶，但不能用“这次峰值只有0.2”反推硬件最大量程。不要为了测饱和做高速撞限位试验。

上游核心实际使用 `0.99×satu_acc`、`0.99×satu_gyro` 作为判断阈值，见[参数读取](../../src/team43_lio_backend/vendor/small_point_lio/src/small_point_lio/parameters.cpp)和[观测更新](../../src/team43_lio_backend/vendor/small_point_lio/src/small_point_lio/estimator.cpp)。阈值应依据真实输入满量程及缩放，过小会丢正常观测，过大不能识别削顶。若改用m/s²输入，acc_norm取9.81，并同步换算satu_acc；不能只改一项，也不将量程阈值当成滤波噪声。

**保存/重启**：记录型号、缩放、实际范围与依据，写LIO配置副本并重启LIO；与源建图使用的外参仍保持同一份。没有依据就保留“未确认”，不要仅关闭check_satu来掩盖问题。

### B2 安装关系：实际拿尺量哪几个位置

**用途**：把LIO内部IMU的位置换到底盘中心，把相机中的码位置沿云台机构换到底盘和比赛坐标。平移可以先粗量，轴向需要明确；两原点相近不能证明旋转为零。

#### B2.1 先在照片上标基准点和方向

1. 保持正常装配，记住车头；底盘系x向前、y向左、z向上。
2. 按题面/机械定义标出底盘中心B，并注明这个原点在什么高度。不要一张照片以地面为z=0，另一张以安装板为z=0而不说明。
3. 标出yaw轴的一条可见基准线和其上可重复找到的基准点Y；标出pitch转轴和基准点P。转轴是一条线，需要选定线上哪一点作为建模原点。
4. 标出G：本项目云台IMU姿态所对应刚体上的一个可重复参考点，记录它相对转轴/板卡的关系。相邻两段使用同一个G，不必猜芯片内部的隐藏测量点。
5. 标出相机光心参考C。优先用可信机械图给出的光心位置；只有镜头/安装面可量时就标“代理点”，并记录未知光心偏移范围。相机的光学轴转换代码已经给出，不另做一份。

把这些点标在照片副本或纸上示意图中即可，不要求画CAD。G的实际轴向沿用已有判轴与安装资料，照片上的任意箭头不能取代轴定义。

#### B2.2 逐条填五行尺量数据

在现场记录第3节，每行先填原始毫米读数。表中的“父←子”表示“子原点在父系中的位置”。

| 记录行 | 尺子量什么 | 取坐标的方向 | 最后填到哪 |
|---|---|---|---|
| 底盘←LIO body | B到厂家定义的内部IMU原点 | 底盘前/左/上 | `localization.sensor_in_base_xyz/rpy` |
| 底盘←yaw基准 | B到Y | 底盘前/左/上 | `kinematics.base_mount_xyz/rpy` |
| yaw转后←pitch基准 | Y到P，记录当时yaw姿态 | yaw转后坐标轴 | `kinematics.yaw_to_pitch_xyz` |
| pitch转后←G | P到G，记录当时pitch姿态 | pitch转后坐标轴 | `kinematics.pitch_gimbal_xyz/rpy` |
| G←camera_link | G到C及相机安装方向 | G坐标轴 | `kinematics.gimbal_camera_xyz/rpy` |

每行按下面顺序操作：

1. 将尺子沿父系的一根轴摆正，量子原点相对父原点的轴向差；前/左/上为正，后/右/下为负。父轴不与底盘平行时按该父轴表达。
2. 三个分量分别量，不能将两点的斜距抄成x。难接近时，从共同安装面量到两点，再相减；图纸能给出内部原点位置时用图纸。
3. 写清读数和误差。例如“前80mm、右20mm、上50mm，估计各±5mm”；这组**示例**换成米为`[0.080,-0.020,0.050]`，不是本机值。
4. 若将很小的一段平移近似为零，写“该段估计不超过×cm，暂取0”；有偏移上界后才能评估误差。雷达离地23.1cm不能直接填成body在底盘系的z，除非两者参考原点关系确实支持。
5. 对旋转，不会填rpy就先写“子x指向父哪边、子y指向哪边、子z指向哪边”，附安装平行面、倾角读数和照片。相机同时记录镜头朝向与图像上方向。只有三轴确实同向，rpy零值才有依据。

**完成标志**：五行都有测量值或明确缺口、参考点照片、朝向依据和误差估计。现场先交原始毫米/度数，由数据处理方统一转米/rpy；脚本不会自动测出这些安装尺寸。

`localization.source_parent_in_output_xyz/rpy`是`odom←lio_world`的坐标约定，若我们明确两系同轴同原点，可以按定义为零，不是再量一只设备。原始记录中注明该约定即可。

### B3 参考零位和工作范围：先建立能重复找到的姿态

**用途**：当前运动学需要从姿态反解yaw/pitch，必须知道“哪个姿态算0、使用哪段单圈区间”。这项不要求测到机械硬端点；图像瞄准成功也不会自动给出机械零位。

#### B3.1 先保持底盘不动，准备朝前/水平的参考

1. 请现场人员让底盘在平整位置停住，记录车头方向；本程序不控制轮子。采集参考姿态期间不要让底盘转向。
2. 从俯视方向用底盘中心线/安装基准表示“朝前”，可在纸上或地面做前向参考线。用正面与侧面照片记录它和相机安装面的关系。
3. 侧面用水平尺或已有倾角工具辅助确认相机安装面的倾角；不要把工具贴在曲面镜头上，也不靠手机罗盘给绝对yaw。
4. 如果装置已经处于可复现参考姿态，直接记录，不必为了本节重新转动。若需要调整，按下一小节选已有可控方式；没有已验证的调整方式时先交当前姿态及照片，不强行手拧带电机构。

**“朝前、水平”是方便操作的物理参考，不自动等于所有安装rpy为0。**相机和G有固定旋转时，由B2资料和这个物理参考一起计算模型偏移。报告关节零位可以按这一参考定义，但`joint_zero_rad`还需要与模型固定边一致，不能抄IMU世界yaw。

#### B3.2 需要小幅调整时怎样操作

当前程序没有“移动到机械yaw=0/pitch=0”的位置指令接口，不要尝试编造这种`ros2 param set`命令。优先沿用现场已验证的人工/固件定位方式，并把它写入记录；也可在已经接近参考、只需小幅修正时，用现有图像闭环辅助对准。

使用图像闭环辅助时，先按B4.1复用/启动终端1；实物旁人员把7.5cm码放到参考方向，相机大致同高、正对镜头，记录码中心位置依据。码只用于辅助对准，最终物理参考仍看机械标记/角度工具；放得大致朝前的码不能单独证明精确yaw=0。

终端4先停止运动，保存调整前配置，再选低速短时模式。导出时motion_enabled已为false，恢复配置不会因此自动开闸：

#### B3.3 拍照、填写姿态说明

参考姿态稳定后拍三张：俯视（能看车头和相机方向）、侧视（能看水平基准）、机械标记/角度工具近照。建议文件名含`reference_top`、`reference_side`、`reference_angle`。

**完成标志**：另一个现场人员能依据标记、照片和基准重复摆回该姿态；不是只有“已经摆正”一句话。B4参考采样可以紧接着做，不用重新摆一次。

#### B3.4 工作区间怎样取得

优先沿用已有主办方联调中的实际姿态记录。需要补充时，只记录比赛所需的左/右/上/下正常工作姿态，注明相对上面的参考零位，不为本表触碰硬端点或额外做全行程试转。没有编码器时，可用安装在底盘基准上的量角器/角度标记读相对yaw，用倾角工具读pitch；同时记录车身是否转动。

记录表“B3工作区间说明卡”分别填四个方向，注明是机械极限、已测试可用位置还是比赛所需范围。当前用户给的“俯仰最高约80°、水平小于180°”直接引用；尚未明确的另一端及零位关系继续留空，不补成±80°。

代码模型正yaw向左、正pitch低头。**若**水平为0且最高80°指上抬80°，该端对应pitch约-1.3963rad；这不证明另一端为+1.3963rad。角度原始记录先保留“左/右/上/下＋度数”，转换交给数据处理方。yaw工作区间宽度须小于2π，pitch加零位后的区间须严格位于(-π/2,π/2)。

最终对应`kinematics.joint_zero_rad`、`yaw_limits_rad`、`pitch_limits_rad`。这些区间用于运动学反解和match比赛模式保护；确认依据后设置`kinematics.joint_limits_confirmed: true`。bench台架模式的`max_rotation`另作试转预算，不能当成机械端点。

#### B4.5 怎样确认包里确实有需要的数据

仍在完成两次采样的终端4，整段复制下面命令。它只读取两份采样包中的JSON，不改参数、不控制设备：

```bash
python3 -B - "$REF_DIR" "$CHECK_DIR" <<'PY'
from pathlib import Path
import json
import sys
all_epochs = []
for name in sys.argv[1:]:
    out = Path(name)
    print('\n目录：', out)
    summary = json.loads((out/'summary.json').read_text())
    print('采样正常结束：', summary.get('collector_completed'))
    for role in ('lio_odom', 'gimbal_imu', 'epoch'):
        state = summary.get('streams', {}).get(role, {})
        print(role, '收到=', state.get('received', 0),
              '状态=', state.get('status'),
              '源时间=', state.get('first_stamp_s'), state.get('last_stamp_s'))
    events = [json.loads(line) for line in (out/'measurements.jsonl').read_text().splitlines()]
    epochs = sorted({event['data']['data'] for event in events if event['role']=='epoch'})
    all_epochs.append(epochs)
    print('本目录epoch原整数：', epochs)
    spans = [summary.get('streams', {}).get(role, {}) for role in ('lio_odom', 'gimbal_imu')]
    if all(state.get('first_stamp_s') is not None and state.get('last_stamp_s') is not None for state in spans):
        start = max(state['first_stamp_s'] for state in spans)
        end = min(state['last_stamp_s'] for state in spans)
        print('源时间范围相交：', end > start, '候选共同范围：', start, end)
    else:
        print('源时间范围相交：无法判断，至少一路没有头时间')
print('\n两目录epoch唯一且相同：', len(all_epochs)==2 and len(all_epochs[0])==1 and all_epochs[0]==all_epochs[1])
print('以上仅检查原始样本和时间范围；未自动确认机械姿态、同步精度或对齐结果。')
PY
```

看输出的五件事：两份均正常结束；三路计数均大于0；LIO/云台源时间范围相交；每份epoch只有一个原整数且两份相同；现场记录证明15秒内物理姿态稳定。epoch没有Header，打印源时间为None正常。

`summary.json`里的`not_received`还可能列出target、map、tick等，这些程序尚未运行/未开赛时正常。它们不影响本次B4原始采样。**三路计数有了，不等于B3零位、外参、物理同步或对齐已经自动确认。**

关了终端4导致变量丢失时，不重采：先加载本次环境，在文件管理器打开`样本与姿态对应.txt`，把两条真实目录路径分别赋给`REF_DIR`、`CHECK_DIR`，再运行上述读取命令。路径含空格时用双引号。

#### B4.6 数据交回后还要做什么

你交回两份目录、B2安装方向、B3两次姿态/照片和保持方式即可，不需要现场手算矩阵。数据处理方从共同时间窗口配对有效四元数，用以下关系计算，参数含义见第7节：

```text
R_odom←base = R_odom←lio_world × R_lio_world←body × (R_base←body)ᵀ
R_odom←G = R_odom←base × R_base←G(已知姿态、固定安装旋转)
R_odom←world = R_odom←G × (R_world←G)ᵀ
```

再用复核姿态核对结果、转成rpy，写入`kinematics.odom_world_rpy`，将原epoch写入`kinematics.calibrated_epoch`。脚本不执行这一步；采样结束后没有自动填妥的整车配置，是正常结果。未知项和近似项留记录，不能把模板所有确认标志直接改为true。

若B2旋转或B3姿态还缺依据，仍可保存原始数据，但对齐计算尚未完成。以后重新启动LIO或IMU惯性参考变化时按第7.3节复核关联；旧包可作分析资料，旧epoch/对齐不能自动套到新会话。

| 设备型号/轴图/内部外参说明 | 现场记录B1＋照片/厂家资料；输入未变换直接沿用 | 内部R/t缺哪份资料 |
| 五条固定边的尺量值/朝向 | 现场记录第3节＋照片 | 原点/方向/尺寸哪一项未确认，近似值误差多大 |
| 参考零位、所需工作区间 | B3说明卡＋参考照片 | 区间哪端没有读数；不以对称假设补齐 |
| 两个姿态样本和对应说明 | 两个alignment目录＋样本与姿态对应.txt＋B4卡 | 三路中缺哪路、是否重启、是否有回落 |
| 源地图及采用依据 | 配置快照＋B5卡＋源地图目录 | 保存失败或地图实际缺陷 |

脚本每个采样目录里的`manual_measurements.yaml`也可填写，已经填现场记录卡的数值不必重复抄；它是人工记录，不是可加载的ROS参数。已确定项由采样器预填来源；null只保留给剩余未知项。现场不会算的rpy/世界对齐保留原始读数和照片即可。

#### B6.2 制作完整交接包

先保存记录，照片已上传的放进photos，尚在手机的注明另附。终端4加载本次环境后执行：

```bash
ARCHIVE_PATH=$(mktemp "$(dirname "$CONFIRM_DIR")/confirmation_complete_XXXXXX.tar.gz")
tar -czf "$ARCHIVE_PATH" -C "$(dirname "$CONFIRM_DIR")" "$(basename "$CONFIRM_DIR")"
printf '完整交接包：%s\n' "$ARCHIVE_PATH"
tar -tzf "$ARCHIVE_PATH"
```

只有tar未报错、且最后的目录清单能正常列出内容，才认为打包完成。`mktemp`生成唯一文件名，原记录和旧包保留。把打印的完整压缩包与另附照片交回分析；不要只发目录里某个旧的alignment自动压缩包，因为它不会随之后填表/加照片而更新。

只有原始采样完成、数据处理方计算并核对几何后，才填写运行参数和相应确认标志，再按[比赛启动与收尾](比赛启动与收尾.md)启动完整处理/提交链。本次采样不要求未开赛时就有map起点、target有效状态或CSV增长。

### B7 卡在哪一步时怎样继续

| 现象 | 下一步具体做法 |
|---|---|
| source路径不存在、找不到包 | 回B0.2核对本队部署目录和现场Livox加载路径，保存第一条错误，不装pip或猜保护目录 |
| 已有程序运行，不知道是否再开 | 先查看它原启动终端；桥/LIO/建图各复用一份，本页启动命令仅用于当前没有实例的情况 |
| 不会把云台移到精确角度 | 用B3的机械标记和已验证方式；没有绝对位置接口，脚本也不能摆姿态。记录原始角度依据，不用运行时长当角度 |
| false后云台回落 | false不是位置保持；联系现场已有保持方式，或记录由人监督的稳定闭环保持。姿态仍变就不算静止样本 |
| 采样目录已存在，退出码2 | 换新后缀/重新运行带时间的目录赋值，不删除旧包；不能把已存在的mktemp目录直接传作采样输出 |
| lio_odom计数为0 | 看终端2是否实际收到点云、是否报字段/时间错误；确认不是只启动雷达驱动而没启动本队LIO |
| gimbal_imu或epoch计数为0 | 看终端1及唯一桥，核对实际话题/类型；名称变化用采样器的--topic覆盖，保留实际命令 |
| 时间范围不相交、年龄巨大或倒退 | 保留headers.csv和会话信息，查时间源/回放/域；不以任意放大超时解决 |
| 两个目录epoch不同 | 记录哪次桥/MCU复位；恢复稳定后在同一会话采一对新样本，旧数据不删 |
| not_received有tick/map/target | 当前只做B4且未开赛/未开处理链时正常，先看三路必要计数，不为凑数据发布测试judge消息 |
| Publish Point点击无输出 | RViz检查工具Topic是否/clicked_point、是否真的选中Publish Point并点在可见点云；终端4保持echo运行 |
| 地面大面积被判成障碍 | 保存状态/截图，核对安装与高度是否变化及当前调平配置；不另开一套旧LIO |
| 源地图等待地面或没有有效扫描 | 按建图教程第4.3节输入实际值，再看status具体原因；没有有效地图时保存服务会失败 |
| 采完不知道下一步填什么 | 先完成B6交回原始材料；脚本不自动算rpy和世界对齐，不能靠把模板true补齐来继续 |
