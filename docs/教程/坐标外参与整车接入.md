# 坐标外参：到了实物面前做什么，怎样接进整车

A 负责坐标关系和独立误差核算，C 量尺寸、摆目标并记测量基准，B 录原始消息、填配置和启动处理链。O/C 已明确，不重新画；云台通信和 G 的 yaw→gz、pitch→gy 关系已有记录，不重新从“无数据”开始。以下解决的是比赛位置与预测，不是桌面跟踪的前置条件。

## 1 先分清“方向”和“原点”

G 的三根轴来自固件输出和已完成的动作观测，不能从照片猜。角速度/四元数能告诉我们转动方向，不能告诉我们板上哪一点是平移原点。本项目不靠积分云台加速度求位置，因此可选可复现的刚体基准点作为 G 建模原点；必须让相邻两条安装尺寸使用同一个点，并记录其相对 IMU/转轴的关系。传感器姿态不能补偿错误的杆臂。历史核查与用户修改原文保存在[已完成的 G 核查记录](../记录/G坐标核查_历史.md)，其中旧部署步骤不再执行。

相机原点是投影模型的光心，镜头前端和外壳边不能直接当光心；查机械图找光轴基准，找不到时记录代理点与未知偏移。当前新 K/D 已收到并用于程序，不要求重标。

## 2 相机到 G 的安装关系怎么测

### 2.1 平移怎么量：量三个分量，不量斜线

目标为`t_G←C=[前后,左右,上下]`，用G轴表达。

1. 保持相机/IMU同一姿态，记照片号和关节状态。
2. 以G原点或已知代理点为起点，用直角尺将相机光心参考投影到G的x、y、z方向，分别量三个距离。可用共同安装面、直角尺、铅垂线辅助；斜线长度不等于任一坐标分量。
3. 难直接量时用共同基准相减。例如同一水平面到两点的高度为hC、hG，竖直差为hC-hG。**若G_z不竖直，这个竖直差不能直接当G_z分量。**
4. 每项量三次，保留mm原值、均值、读数波动、光心代理误差。精度来自量具和基准，不随意写“毫米级标定”。
5. A换算米：80mm=0.080m。前/左/上为正，后/右/下为负。

例：相机在IMU前80mm、右20mm、上50mm，则`t_G←C=(0.080,-0.020,0.050)m`。**这是符号例子，不是本机参数。**

光心位置未知时，交“机械初值＋未知偏移范围”，再用第5节检验；不能宣称外参标定完成。

### 2.2 旋转怎么确定：光轴方向还不够

旋转矩阵三列分别是C的x/y/z单位轴在G里的方向。所以必须同时确认光轴和图像上方向；只确认镜头朝前，仍不能确定滚转。

- 有可信图纸/平行机械基准，且C_x/C_y/C_z分别与G_x/G_y/G_z同向，可将`R_G←C=I`作为有依据的安装初值；肉眼“差不多”不等于精确零角度。
- 有倾角时，选G上已知的两条不平行基准，与相机光轴/图像上方向关联的机械基准比较。用角度工具量的是**两者相对方向**；只量相机对桌面的角度，不能得到相机对IMU的角度。
- A使用已经明确的轴写旋转矩阵，B再按统一`R=Rz(yaw)Ry(pitch)Rx(roll)`转配置；顺序roll,pitch,yaw，单位rad。正yaw把+x转向+y，正pitch把+x转向-z。不要靠试正负调到看着对。
- 有测量方向向量时，检查单位长度、正交性、右手性，要求`RᵀR≈I、det(R)≈1`。三条不正交测量向量不能直接当精确旋转矩阵。

缺G的方向基准、光轴关联或需要更高精度时，要补独立标定数据。先做第5节的共同基准位置实验，再决定是否需要进一步标定。**一张ArUco图只给码相对相机的位置；一个IMU四元数只给姿态；它们不能凭空给出IMU—相机平移。**

已知的光学约定是：

\[
R_{C\leftarrow O}=\begin{bmatrix}0&0&1\\-1&0&0\\0&-1&0\end{bmatrix},\qquad p_C=(z_O,-x_O,-y_O).
\]

完整关系为：

\[
p_G=R_{G\leftarrow C}R_{C\leftarrow O}p_O+t_{G\leftarrow C}.
\]

教学URDF的固定光学关节只给`C←O`，不替你测`G←C`。假设安装同向并使用2.1的虚构平移，`p_O=(0.10,0.05,2.00)m`应算成`p_G=(2.08,-0.12,0.00)m`；图像右下对应G系偏右、偏下，方向应能解释。

## 3 底盘、雷达、转轴按同样标准记录

画链：`底盘B → yaw基准 → pitch基准 → IMU G → 相机C → 光学O`，另有`底盘B → 雷达参考S`。L留给定位系使用，不复用同一字母。

1. 雷达最终与底盘固定后，`T_B←S`是常量。原点/轴用厂家参考或驱动定义，不能以玻璃罩顶点替代。
2. 转轴是一条线，不天然规定线上哪一点是原点。选一个可复现安装面交点等作为参考，写清依据。
3. 每条平移用**父坐标系的轴**表示，不把不同关节的“前左上”统统当底盘轴。
4. 关节转动时相机相对底盘变化；某一姿态量出的`T_B←G`不能当全程常量。
5. IMU不在转轴交点时，转动还带来原点平移；四元数本身不能补杠杆臂。

A交B的每条边须包含：父/子、原点和轴、固定/变化、数值/单位、来源/误差、测量时关节状态和未知项。不能只交五组无方向的尺寸。

## 4 IMU世界、LIO和比赛起点，现场如何对齐

L表示自有定位系，W表示云台IMU惯性系，M表示比赛起点系。不能因都叫world/map就当相同。

协议q满足`v_W=R(q)v_G`。TF边名`world→gimbal_link`指父子关系，不是让你把这个点变换取逆。就绪时yaw=0是IMU参考，不等于云台朝车头；固件复位后需重新对齐。

现场流程：

1. A/C确认一个可复现、方向已知的云台相对底盘姿态，写下机械零位/关节角依据。只说“看着朝前”不够。
2. 整套装置静止，B同时录自有LIO和云台IMU约5—10秒，保留stamp，A/C记实际姿态。不能拿不同时刻的两条echo当同步证据。
3. 先把LIO参考点换到底盘；结合已知机械姿态得到`R_L←G=R_L←B R_B←G`。
4. 取同一静止窗口有效的`R_W←G`，求`R_L←W=R_L←G (R_W←G)ᵀ`。这里只解旋转，平移还须用原点与运动链。
5. 用另一个已知姿态独立核验；静止窗口减少时间误差，不代表传感器时延已标定。

若第1步缺失，公式不能生成可靠结果。重力能约束倾斜，不能单独给绝对yaw；应补零位/相对朝向依据或另设计标定实验，不把默认`world_odom_xyz_rpy`全0当答案。

比赛起点：取**起点时刻底盘中心**的`p0,ψ0`，使用：

\[
p_M=R_z(-\psi_0)(p_L-p_0),\qquad v_M=R_z(-\psi_0)v_L.
\]

先做传感器到中心的换算，再冻结起点；不是程序启动后任意第一帧。验证样例：`p0=(2,-1),ψ0=90°`，则`(2,-1)→(0,0)、(2,0)→(1,0)、(1,-1)→(0,1)`；速度`(0,1)→(1,0)`，只旋转不减起点。复用`freeze_T_map_odom()`及既有A样例。

## 5 外参量完怎样验：两层实验

**第一层：光学方向和距离。**按B2摆码、看x/y/z。码像素中心靠近内参主点`(710.01,562.53)`时x/y接近0；它不等于图像几何中心。此实验不能证明全部安装外参。

**第二层：安装变换。**需要独立知道码中心在G系中的`p_G真`，不能拿同一相机待验证的结果当真值。

1. 相机和G保持固定。用G原点/代理点及已知轴建立共同测量基准，用尺/网格/直角尺摆至少6个位置，覆盖近远、左右和不同高度，避免全在一条直线上。
2. A/C独立测每个码中心的三维分量及误差；B每位置录约5秒`p_O`、有效性、重投影误差。
3. 算`p_G算=R_G←C R_C←O p_O+t_G←C`，逐点对照独立测量，记三轴和总误差。
4. 调整初值只用其中一部分位置，留至少2个未参与调整的位置验收。

如果机械基准无法给出足够准确的旋转，但已独立量出这些点在G中的三维坐标，A可在同一组点对上做成熟的三维刚体配准：求使`Σ||p_G真-(R_G←O p_O+t_G←O)||²`最小的R/t，约束R为旋转矩阵。用去中心化点对、SVD和行列式修正即可，不必一开始上完整手眼标定。此时拟合结果已包含光学轴转换，`R_G←C=R_G←O (R_C←O)ᵀ`，不能再多乘一次。只有单张图、G原点/轴未定义或所有点真值仍由同一相机推算时，这条路也不成立。先完成测量/验证，再按残差决定是否需要拟合，不把它额外强加为第一轮任务。

旋转可信、平移存疑时，可检查`t_i=p_G真-R_G←C R_C←O p_O`是否接近常量，再估计平移均值。误差随距离放大，先查旋转、K和码尺寸；恒定偏移先查原点；随方位变化先查旋转/畸变/符号。这是排查线索，不是仅凭现象确定原因。

团队初始排错门槛：1—3m且独立测量足够准确时，位置误差不超过`max(0.03m,距离×3%)`。不是官方标准或最终成绩保证。测量基准本身不准，就标“未验证”，不放宽阈值强行通过。


刚体变换的顺序参考[主办方第一课](https://blog.secaumene.com/teach/class-1.html)；相机光心、K/D、PnP 与安装外参的区别参考[第二课](https://blog.secaumene.com/teach/class-2.html)。测量值、正负号和代理点写进[现场记录表](../记录模板/现场记录表.md)，无需另建一套文档。

## 6 装车参数只填这一份

运行外参只填写 `src/team43_bringup/config/vehicle_template.yaml` 的个人副本。代码已补充每项物理含义、方向和单位：xyz为米、rpy为弧度，`T_A←B`把B中的点换算到A，xyz为B原点在A中的位置。

| 参数 | 填什么 | 当前状态 |
|---|---|---|
| `localization.sensor_in_base_xyz/rpy` | Point-LIO的IMU body在底盘中心坐标中的安装位姿，不是雷达外壳的位置 | 最终装车后填写 |
| `localization.source_parent_in_output_xyz/rpy` | camera_init到我们odom的坐标约定 | 可按定义选择同轴同原点的identity；确认的是约定，非另测一只传感器 |
| `kinematics.base_mount_xyz/rpy` | 底盘中心到yaw安装基准 | 最终安装后填写 |
| `kinematics.yaw_to_pitch_xyz` | yaw转后坐标中，yaw基准到pitch转轴的偏移 | 物理安装尺寸 |
| `kinematics.pitch_gimbal_xyz/rpy` | pitch转后到G参考点和轴的固定关系 | 参考点需明确，和下一项保持一致 |
| `kinematics.gimbal_camera_xyz/rpy` | camera_link在G中的固定安装关系 | 相机已固定，可整理已有测量；不要求重画O/C |
| `kinematics.odom_world_rpy/calibrated_epoch` | IMU姿态参考世界和LIO世界的对齐及对应上电会话 | 用同次姿态数据对齐，不拿世界yaw当机械零位 |

模板中的零值仍是未确认占位，确认标志保持false；不能为了启动而全部改成true。相机新K/D从 `camera_team43.yaml` 读取，雷达内部雷达↔IMU偏移从 `small_point_lio_mid360.yaml` 读取，不再复制多份常量。

比赛坐标沿用代码名 `map`：按 `/judge/replay_start` 对应时间的**底盘中心**位姿冻结，原点在该中心，x为初始车头的平面方向，y为初始左侧。转换顺序是：

```text
相机光学点 → 固定相机安装关系 → 当前yaw/pitch转动 → 底盘中心
           → 当前LIO位姿 → 比赛起点坐标
```

LIO给的是IMU位置，先用安装外参扣除杠杆臂，再求底盘中心；不能先把IMU初始位置当底盘初始位置。地图源frame现在明确为 `camera_init`，通过真实TF转换到map。既有原点冻结、非零初始yaw和杆臂测试复用，不重新发明一套坐标接口。

G的参考原点是我们建模时要定义清楚的刚体参考点；orientation本身不能告诉你这个点在板子哪里。本链用云台IMU的姿态，不把未确认的加速度测量点拿来积分位移；不再以寻找固件中的“神秘原点”为由阻塞图像跟踪。


B 在已安装、source 本包的 NUC 终端，把模板复制到本队目录再编辑：

```bash
cp -n "$TRACK_WS/src/team43_bringup/config/vehicle_template.yaml" "$TRACK_WS/vehicle43.yaml"
```

文件若已存在，继续编辑原来的实测副本，不覆盖成空模板。每个 true 对应一项实际完成的测量/定义，未测不置 true。rpy 按 roll,pitch,yaw，单位 rad，旋转为 Rz(yaw)Ry(pitch)Rx(roll)；用非零角和偏移独立算一次，不能只验全零。

## 7 B 录同步数据、再启动处理链

最终装车且有已知云台姿态后，B 在同一个 ROS 域同时录 5～10 秒：

```bash
ros2 bag record -o "$TRACK_WS/alignment_01" /red_standard_robot1/gimbal /red_standard_robot1/aft_mapped_to_init /task1/gimbal_reset_epoch
```

Ctrl+C 结束。A/C 记这一段的实际姿态与零位；第 4 节用同一静止窗口求对齐旋转。不要拿两个不同时刻的 echo 代替同步记录。桥的 IMU stamp 是主机收到帧时刻，Point-LIO 用其激光末时刻；静止对齐不等于已经标定传感器时延。

配置填写且核对唯一 TF 发布者后，另开保留原 ROS 环境的终端，source 本包 install/local_setup.bash，再运行：

```bash
ros2 launch team43_bringup processing.launch.py vehicle_config:="$TRACK_WS/vehicle43.yaml" target_id:=0 submission:=false
```

它启动底盘转换、起点、云台几何、感知、预测、地图转换和方向建议，不开驱动/串口/电机。它的公共感知话题与桌面跟踪的 /team43_tracking/* 隔离，可以共享原图；别另外再启动一份旧全量入口。

B 在另一个同环境终端输入：

```bash
ros2 topic echo /gimbal/base_pose_raw --once --qos-reliability best_effort
ros2 run tf2_ros tf2_echo map camera_optical_frame
```

第一条应是 odom/base_link，参考点已换到底盘中心、stamp 保留源时间。第二条等真实 replay_start 的历史位姿覆盖后才应查到完整链；Ctrl+C 结束查看。开赛信号之前等待是正常的，不用单位阵/最新位置假装起点，不向 /judge/* 发测试信号。正式回放中继续看：

```bash
ros2 topic echo /estimation/target_state --once --qos-reliability best_effort
ros2 topic echo /chassis/advice --once --qos-reliability best_effort
```

应分别有 map 中的有效目标状态、建议速度；相机/底盘/地图过期时应显式无效，不能把“有消息”当作精度通过。TF 的数字与实测尺寸、独立目标位置都一致后，停止这个实例，再用同一配置改 `submission:=true team_id:=43 output_dir:=$HOME/ws_championship/output`，只启动一个提交器。准备好后按主办方流程写正式 43.csv、43_map.pgm/yaml；不修补已经提交的行。

## 8 时间与预测，怎样验而不是只看平滑

| 接口 | 内容及时间含义 |
|---|---|
| `/perception/marker_cam`，`team43_interfaces/msg/MarkerObservation` | `header.stamp` 是原图像时间；`frame_id=camera_optical_frame`；`x,y,z` 单位米；`marker_id,valid,cov_optical` 表示识别结果与不确定性。桌面跟踪入口会把它隔离到 `/team43_tracking/marker_cam` |
| `/gimbal/base_pose_raw`，`nav_msgs/msg/Odometry` | 已换算到底盘中心的自有里程计，`header.frame_id=odom`、`child_frame_id=base_link`；保留原始测量时间 |
| `/judge/replay_start` → `map→odom` | 用该消息时间对应的底盘位姿冻结原点，不拿消息抵达时的最新位置代替 |
| `/gimbal/base_pose`，`nav_msgs/msg/Odometry` | 位置已在 `map`；标准 Odometry 的 twist 仍以 `child_frame_id=base_link` 表达，提交器会旋转到 `map` 后使用 |
| `/estimation/target_state`，`team43_interfaces/msg/TargetState` | `header.frame_id=map`；`cur_x,cur_y` 对应该消息 `header.stamp`，`pred_x,pred_y` 对应该时刻+0.1 秒；另含 `vel_x,vel_y,acc_x,acc_y,cov_xy,valid,track_status,last_obs_age` |
| `/chassis/advice`，`team43_interfaces/msg/ChassisAdvice` | `header.frame_id=map`；`cmd_vx,cmd_vy` 是建议底盘速度，不是实际驱动底盘的指令 |
| 九列 CSV | `pred_x,pred_y,cur_x,cur_y,base_x,base_y,vx,vy,t_tick`。提交器重新按本拍时间采样，因此不能直接把较早那条目标消息整行抄入 |

例如图像观测时刻为 10.00 秒，tick 是 10.04 秒，目标速度为 `(0.4,-0.2) m/s`：先把当前位置推进到 10.04 秒，再把预测位置推进到 10.14 秒。源码中的 `StampedTracker.sample()` 和 `TickSampler.sample()` 已处理这件事。A 可以对照离线 `verify_timing_offline.py` 中 `test_tick_uses_prior_state_and_projects_both_times`，不必另造预测接口。

下一步把真实记录接进这些现成接口，比较误差；目前仍没有真实地图坐标的目标轨迹可据此宣称预测精度。刚体变换的乘法顺序可参考[官方第一课](https://blog.secaumene.com/teach/class-1.html)，相机三维位置参考[官方第二课](https://blog.secaumene.com/teach/class-2.html)。这些坐标工作服务于比赛定位，不作为桌面图像跟踪的前置条件。




在已 source 本包的终端可独立跑合成预测：

