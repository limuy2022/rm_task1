# PnP 视线跟踪：备选台架与整车试转

这是远端新增的另一套跟踪链：检测 → PnP → gimbal_bearing_node → 适配器 → 串口桥。你们当前先试的直接图像跟踪仍按[云台跟踪教程](云台跟踪.md)操作。**两套程序都保留，但不能同时打开同一串口。**本页不要求重新做已确认的通信和 O/C/G 轴向工作。

本页针对 bearing_bench / bearing_hardware；它们不是 visual_tracking 的调参方法。仿真记录不代表实际云台已经验收。

## 静止台架分步操作（来自远端新增教程）

适用场景：**车身固定不动**（轮子锁死/压重、上电时大致放平），只想验证"打印码 → 相机 → 检测 → PnP → 轴承闭环 → 串口 → 云台转向码"这条链本身。跳过全部测量（几何按零假设），入口为 `bearing_bench.launch.py`（用法详见其文件头）。

台架假设的代价（接受才往下走）：yaw 关节角带一个未知常数偏差（IMU 上电朝向随机）→ **PC 侧软限位不可信**，依赖固件编码器限位 + 低速预设 + 人工断电兜底；pitch 是重力基准的，仍然正确；瞄准误差来自图像，不受影响。跑通后转实测流程：本文最后一节 + `bearing_hardware.launch.py` + 实测整车参数。

前置硬件：云台 USB（本队 `/dev/ttyUSB0`）、相机已在发 `/image_raw`（官方驱动，本程序不含）、一张 **10cm 边长**的 DICT_4X4_50 ArUco 码（记住 ID），贴 1.5–2.5m 外、与相机大致同高、正对前方。全程手握电源开关。

---

## 第 0 步：一次性环境准备（只做一次）

```bash
# 在个人 Ubuntu 的独立开发副本执行；公共 NUC 仍使用本队独立部署目录
cd <仓库目录>
source /opt/ros/humble/setup.bash
mkdir -p build
touch build/COLCON_IGNORE          # 防止 colcon 扫进 build 目录
colcon build --symlink-install --paths src/*
source install/setup.bash
```

## 第 1 步：每次上电的固定动作（约 3 分钟）

```bash
export ROS_LOCALHOST_ONLY=1

# 1a. 读本会上电的 epoch（每次上电都会变，记下数值）
ros2 topic echo /task1/gimbal_reset_epoch --once \
  --qos-reliability reliable --qos-durability transient_local

# 1b. 确认 0x01 反馈在流（Publisher count 应为 1，echo 连续有输出）
ros2 topic info /red_standard_robot1/gimbal --verbose
ros2 topic echo /red_standard_robot1/gimbal --qos-reliability reliable
```

1c. 已有轴向记录时直接沿用；只有接线或安装改变才重新核对，不带电强扳电机。原教程的轴向判据是：手转云台对照 echo 中四元数/陀螺方向。正向规定：下发正 yaw 指令 ↔ `gz` 同向、正 pitch 指令 ↔ `gy` 同向（协议§13）。结论记为 `yaw_sign` / `pitch_sign`（+1 或 −1）。本队已记录轴参数 [1,1,1]；指令方向仍以低速闭环的实际效果判断。

## 第 2 步：只读启动（云台不会动）

```bash
ros2 launch gimbal_tracker_bringup bearing_bench.launch.py \
  epoch:=<1a读到的值>  target_id:=<打印码的ID> \
  port:=/dev/ttyUSB0  yaw_sign:=<±1>  pitch_sign:=<±1>
```

另开终端验证**两条判据都过**才算数据链通：

```bash
ros2 topic echo /gimbal/joint_states --once --qos-reliability best_effort
#   → 有输出且持续；手动俯仰云台时第二个数（pitch）应跟着变（只读安全）

ros2 topic echo /perception/marker_cam --once --qos-reliability best_effort
#   → 相机对准打印码时 valid: true
```

## 第 3 步：桥订阅指令（云台仍不会动）

`Ctrl+C` 停掉，原命令**追加** `allow_command_subscription:=true` 重启。确认云台静止（后两道开关还关着）。

## 第 4 步：闭环开转

再停掉，四开关全开重启：

```bash
ros2 launch gimbal_tracker_bringup bearing_bench.launch.py \
  epoch:=<值> target_id:=<ID> port:=/dev/ttyUSB0 yaw_sign:=<±1> pitch_sign:=<±1> \
  allow_command_subscription:=true control_enabled:=true \
  bearing_enabled:=true geometry_verified:=true
```

**预期**：几秒内云台以低速（预设 ≤0.5 rad/s）转向打印码，码回到画面中心后停住。

## 现场判据与处置

| 现象 | 处置 |
|---|---|
| 平滑转向码并停住 | ✅ 成功。再验停止：遮挡码 ≥0.5s → 云台应减速停止 |
| 朝反方向转 | 立即断电；`yaw_sign` 取反，从第 2 步重来（不得改误差符号绕过） |
| 过冲/来回振荡不停 | `Ctrl+C`；kp 在线降到 0.3 再试（检测延迟大所致） |
| 不动，日志 `no-joints` | 查 `/gimbal/joint_states`：epoch 不匹配或 IMU 断流 |
| 不动，日志 `no-marker` | 相机是否发图、码 ID/边长与参数是否一致、码是否在视野内 |
| 桥启动即 FATAL 串口打不开 | 端口名/占用（`ls /dev/ttyUSB*`、是否已有第二个桥） |

停止可先设 `ros2 param set /gimbal_bearing_node control.bearing.enabled false`，再在启动终端 Ctrl+C。协议约定无新指令约 0.5 秒开始减速、约 3.5 秒松弛；这不是本轮实测的停转保证，异常时由现场人员停机。

## 跑通之后

- 在线提速（不用重启）：`ros2 param set /gimbal_bearing_node control.kp_yaw 1.0`（pitch 同款；逐档升，观察是否振荡）。kp 上限由实测检测延迟决定——仿真实测 kp=6 在 0.5s 延迟下过冲丢码。
- 记录本次试转参数与现象（kp/omega_max、角误差目测、遮挡停止行为），填入现场记录表。
- 转正式流程：量整车参数（[坐标外参与整车接入](坐标外参与整车接入.md)）→ `bearing_hardware.launch.py`；台架入口仅限静止场景。
- 更多参数速查：`src/gimbal_control/gimbal_control/gimbal_bearing_node.py` 文件头；仿真证据与已知坑：[轴承闭环仿真验证](../验证/轴承闭环仿真验证.md)。


## 最终装车后接入实测参数（原手册 B5 的新增内容迁入此处）

这一节用于 bearing_hardware，不用于当前直接图像跟踪。先按[坐标外参与整车接入](坐标外参与整车接入.md)填写真实安装尺寸、零位/限位和同次上电的 calibrated_epoch；这套旧视线控制要求相机与 G 的旋转外参近似为零，不能为了启动而把真实旋转填成零。

1. 先只观察，四个开关保持默认关闭：

```bash
ros2 launch gimbal_tracker_bringup bearing_hardware.launch.py vehicle_config:=/实际绝对路径/vehicle47.yaml target_id:=0 port:=/dev/ttyUSB0
```

应有持续的 /gimbal/joint_states；码在画面中时 /perception/marker_cam 的 valid 为 true。此时云台不动。状态不满足就保留具体报错。

2. Ctrl+C 停这份程序。按同一配置重启，桥允许订阅、适配器允许转发，但 bearing 仍关闭：

```bash
ros2 launch gimbal_tracker_bringup bearing_hardware.launch.py vehicle_config:=/实际绝对路径/vehicle47.yaml target_id:=0 port:=/dev/ttyUSB0 allow_command_subscription:=true control_enabled:=true bearing_enabled:=false geometry_verified:=true
```

geometry_verified 只在实际满足上述安装条件后填写。另开同环境终端，先降低增益和上限，再开 bearing；不要先用 param set 改低，然后重启丢掉刚设的值：

```bash
ros2 param set /gimbal_bearing_node control.kp_yaw 0.5
ros2 param set /gimbal_bearing_node control.kp_pitch 0.5
ros2 param set /gimbal_bearing_node control.omega_max_yaw 0.5
ros2 param set /gimbal_bearing_node control.omega_max_pitch 0.5
ros2 param set /gimbal_bearing_node control.bearing.enabled true
```

3. A 小幅移动码、C 观察电线和活动范围：相机应朝码转，误差减小。试验目标为 30 秒无持续摆动、码保持在画面中心附近；原手册的 RMS<2° 是待实测的团队目标，不是已获得的成绩。遮码超过 max_age 时应停止输出有效指令；epoch 改变应报 epoch-reset，重新对齐后再关→开 bearing。

增益须结合“图像 stamp 到 marker_cam 到达”的实际延迟调整。远端仿真报告在约 0.5 秒检测延迟下，kp=6 会过冲丢码，因此这里从 0.5 起步；不要为放过过期消息无限调大 max_age。记录增益、速度上限、实际误差、丢码与停止现象。

这套程序与旧 world 控制器共用 /gimbal/cmd_omega，不同时运行 gimbal_controller_node、competition 主链、当前 visual_tracking 串口桥。下位机真实控制算法与制动时间仍以固件和实机证据为准。
