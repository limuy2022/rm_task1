## 本轮发现并修复的问题

1. **`gimbal_common/log_utils` 在 ROS 上混用日志等级即崩溃（存量 P0）**：rclpy 按调用点帧缓存日志上下文，旧 `_emit/_FormatLogger.emit` 把所有等级收敛到同一帧，任何节点 INFO 后再 WARN 会抛 `ValueError: Logger severity cannot be changed between calls.`。旧 world 控制器在 ROS 上实跑同样会崩（此前从未在 ROS 上运行所以未暴露）。已按严重级拆分入口函数修复 + 回归测试。
2. **仿真链关节角/epoch 缺失**：competition/sim 阶梯不含 `gimbal_kinematics_node`，且 vgimbal 桥不发布 epoch——kinematics 的 `ready` 要求 `epoch == calibrated_epoch`，故仿真链从未具备关节角来源。已在 bearing_sim 链补齐。
3. **launch 子进程残留污染**：`pkill ros2 launch` 不杀子进程，残留的检测器/视觉节点会共享话题互相污染（多发布者、旧姿态 GT），症状是"云台冻结在旧角度"。每次仿真前必须清残留（`build/run_bearing_sim.sh` 已内置）。
4. **延迟-增益稳定性（对实机调参的预警）**：容器 CPU 饥饿下检测端到端延迟 0.2–0.6s，实机默认 kp=6 在此延迟下**向正确方向过冲 3 倍、码冲出视场丢失死锁**；kp=0.5 时收敛。含义：**实机上 kp 与 `control.bearing.max_age_s` 必须按实测检测延迟整定**（D5 检查单已加入该项），不能照搬任一组数值。
5. edu 工具语义备注：`virtual_vision` 的 static 轨迹目标方位由 `yaw_offset/pitch_offset` 决定（`yaw_amp` 仅对 sine/circle/scan 生效）。

## 仿真与实机的参数差异（勿照抄）

| 参数 | 仿真值 | 实机默认 | 原因 |
|---|---|---|---|
| `control.kp_yaw/pitch` | 0.5 | 6.0 | 容器检测延迟大；实机按实测延迟整定 |
| `control.bearing.max_age_s` | 0.8 | 0.15 | 同上 |
| `perception.detect_rate_hz` | 10 | 30 | 容器 CPU |
| 相机分辨率 | 640×480 | 1440×1080 | 640 下检测快一个数量级；PnP 内参加来自 `/virtual_gimbal/camera_info` 自动一致 |

仿真专用的低增益/宽窗口/低频只写在 `vehicle_sim.yaml` 与 `bearing_sim.launch.py`，`tracker_params.yaml` 中的正式默认值未动。
