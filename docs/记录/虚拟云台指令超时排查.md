# 虚拟云台指令超时排查（2026-10-29）

## 现象与原因

`bearing_sim.launch.py` 持续打印 `cmd timeout, ACTIVE -> DECEL`，但静态目标的
角误差评估仍可通过。原代码复现时约 11 秒只发送 22 帧。

`SerialPort.read_bytes()` 在 `in_waiting == 0` 时仍调用带超时的 `read(256)`。
IMU 持续到达时，桥的读空循环不断等待下一帧，直到达到循环上限才返回。
接收、发送和订阅使用同一个执行线程，因此发送定时器被饿死。
修复为空缓冲立即返回，只读取已经到达的字节。

另一个漏拍原因是 `cmd_due()` 每次用实际回调时间重新计算下一周期，微小抖动
就会使下一拍被拒绝。现在按固定相位推进；长时间停顿跳过错过的周期，不补发积压指令。

自动结束时，bearing 节点原先在 ROS context 已关闭后才发停止消息。
现在保留 Python SIGINT 处理，先执行停止发布再关闭 context；关节节点捕获正常
KeyboardInterrupt。launch 在启动评估器前创建输出父目录，防止运行结束才发现无法落盘。

## 验证结果

在根 Dockerfile 的 Humble 测试容器中构建工作区，构建与安装目录放 `/tmp`。
新增真实 PTY 空缓冲轮询回归，原实现等待约 0.5 秒并失败，修复后通过；
新增定时器抖动与长停顿回归。

- Python：557 项通过。
- C++ 串口桥：36 项通过，无失败或跳过。
- `verify_all_offline.py --skip-pytest`：19 项通过。
- 最终闭环：独立 ROS 域 118，完整评估 30 秒，`complete=true`、`pass=true`。
- 收敛约 1.993 秒；稳态 RMS 0.3009°，最大误差 1.6123°。
- 桥发送 1575 帧，约 50 Hz，无指令超时或串口读写错误；所有节点正常退出。
- JSON/CSV 自动落盘；独立评分复算 RMS 一致，无采样丢失间隙。

原始日志及结果在 `build/offline/bearing_debug/`（不提交），最终结果在
`isolated/final.json`、`isolated/final.csv`，日志为 `isolated.log`。
一次与离线脚本共用 ROS 域的运行发现话题干扰，已丢弃，以上数据仅取独立域复测。

## 重跑

进入按测试指南准备的容器后执行：

```bash
source /opt/ros/humble/setup.bash
source /opt/livox/install/setup.bash
colcon --log-base /tmp/clog build --build-base /tmp/cb \
  --install-base /tmp/ci --symlink-install
source /tmp/ci/setup.bash
export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=118

ros2 launch team43_bringup bearing_sim.launch.py \
  target_id:=0 eval_duration:=30.0 \
  eval_output:=/workspace/build/offline/bearing_demo/final.json \
  eval_series:=/workspace/build/offline/bearing_demo/final.csv

# 参数是文件名前缀（包含 final），不是目录。
python3 -B tools/score_bearing_sim.py build/offline/bearing_demo/final
```

不要与其他测试共用 ROS 域；同域查看图像的终端也需设置相同域。
日志出现 `/workspace/install/...` 而预期使用 `/tmp/ci/...` 时，应检查是否加载了旧工作区。

本轮未修改上游 `virtual_gimbal` 子模块。其评估器提前中断仍可能打印 PASS，
文件写入失败也未必改变退出码，因此验收必须同时检查 `complete`、`pass`、
实际输出文件和各节点正常退出。以上验证为静态合成目标，不代表真实硬件或移动目标验收。
