# 本轮装车配置与近似依据

来源：[现场外参原始记录](../../data/现场外参记录.md)。用户随后确认：相机位置是在水平朝车头时量取，并授权使用机械代理点、理想轴向和近似世界对齐，先补齐可运行配置；15:44采样之后雷达安装角度与位置没有改变，可沿用当时重力方向。原始“待测/待验证”不改成实测成功。

本轮配置单一来源为[vehicle_field.yaml](../../src/team43_bringup/config/vehicle_field.yaml)，随bringup包安装。start_match.bash固定默认加载它，无需传参；需要其他配置时显式传vehicle_config，个人vehicle43.yaml不会自动替换本轮默认值。无需把这些数值再抄进各功能包；`vehicle_template.yaml`保留为通用模板。

## 坐标基准和已落地的数值

B原点选圆柱上表面圆心，离地0.240m，x前/y左/z上。P为两轴模型交点，G位置原点按定义与P重合；G不是实际IMU芯片的平移原点。比赛评分只用底盘x/y，本轮不另猜底盘中心离地高度。

| 运行字段 | 本轮数值（m/rad） | 依据与性质 |
|---|---|---|
| `kinematics.base_mount_xyz` | `[0,0.030,0.060]` | yaw下表面高0.300m减B高0.240m；向左0.030m；x=0为草图初值 |
| `kinematics.yaw_to_pitch_xyz` | `[0,0,0.080]` | P高0.380m减yaw下表面0.300m；选P在轴线交点 |
| `kinematics.pitch_gimbal_xyz` | `[0,0,0]` | G与P同原点的建模定义，不是IMU芯片在P的实测 |
| `kinematics.gimbal_camera_xyz` | `[0.0625,0,0.025]` | 镜头前端代理点；按用户允许近似为光心，镜头内部光心偏移未测 |
| 固定安装`base_mount_rpy/pitch_gimbal_rpy/gimbal_camera_rpy` | `[0,0,0]` | 理想正交两轴、G轴和相机link轴同向的授权近似 |
| `kinematics.joint_zero_rad` | `[0,0]` | 水平朝车头定义为模型参考零姿态，不是编码器读数或IMU惯性yaw零值 |
| `kinematics.yaw_limits_rad` | `[-1.3962634,+1.3962634]` | 本轮记录的左右各约80°；控制器另留0.035rad内侧余量 |
| `kinematics.pitch_limits_rad` | `[-0.7853982,+1.0471976]` | 上仰45°、下俯60°；模型低头为正，不能照搬物理仰角符号 |
| `localization.sensor_in_base_xyz` | `[0.1611558,-0.0099114,-0.0556674]` | 将银圈代理点近似为LiDAR原点后，换算为内部IMU body原点 |
| `localization.sensor_in_base_rpy` | `[-0.7735759,0.0323277,-1.5377129]` | 静止重力方向确定倾斜；银圈法线近似LiDAR+z，其水平投影按记录朝车头 |

## 雷达原点、安装角与地面怎样统一

本轮银圈代理点在B中为`[0.175,0,-0.0075]m`，圆心离地`(0.255+0.210)/2=0.2325m`。用户授权把它近似为LiDAR输出原点，不能把这个位置直接抄给内部IMU body。

内部固定变换仍为配置中`T_IMU←LiDAR`：R=I、t=`[-0.011,-0.02329,0.04412]m`。因此：

```text
R_B←IMU = 先按静止重力调平，再绕竖直轴将近似银圈法线投影对到车头
t_B←IMU = t_B←LiDAR − R_B←IMU × t_IMU←LiDAR
```

转换只做一次。安装与LIO输出采用同一个重力方向；倾斜被消除后，底盘初始姿态近似水平，世界yaw可以非零，正式起点再按车头方向归零；不能把“body安装旋转为零”与“输出已经调平”同时假定。

本轮将LIO配置`lidar_height_m`改为0.2325；调平后的光心到内部IMU竖直偏移约0.0481674m，故`floor_z≈0.0481674−0.2325=−0.1843326m`。换到底盘B原点参考后地面为−0.240m，与本轮B高度一致。原先23.1cm是旧的未指明参考点读数，不声称与本轮银圈是同一点。

圆面尺寸推导的法线仰角53.13°和静止IMU估计的倾斜约44.35°对应不同对象，目前不强行认成同一传感器轴，不把53.13°写入内部外参。本轮倾斜采用重力依据，水平朝向则采用银圈法线近似为LiDAR+z、其水平投影朝车头的授权理想模型。

核对参考：[MID-360官方下载页](https://www.livoxtech.com/mid-360/downloads)及[用户手册v1.2坐标图](https://terra-1-g.djicdn.com/851d20f7b9f64838a34cd02351370894/Livox/Livox_Mid-360_User_Manual_EN.pdf)。官方坐标图并不能单凭用户所指外部银圈确定本轮代理点偏移，因此上述代理关系仍保留近似标签。

## 启动时怎样建立世界对齐

本轮`kinematics.align_world_at_start=true`。启动前使底盘静止、云台相机水平朝车头，并保持到日志提示“按启动水平朝前参考完成世界对齐”；首次匹配到同一源时间的底盘姿态和云台IMU后，程序计算：

```text
R_odom←IMUworld = R_odom←base × R_base←G(参考yaw=0,pitch=0) × transpose(R_IMUworld←G)
```

无需手抄epoch或两个世界的欧拉角。程序不从四元数判断相机是否真的摆正，摆姿态是此近似的物理前提；若启动时已经偏转，偏转会被吸收进参考旋转。运行中不反复对齐，防止把跟踪动作抵消掉；MCU/桥复位仍锁停。

可选只读观察（额外终端先加载同一ROS、本队安装环境）：

```bash
ros2 param get --no-daemon /gimbal_kinematics_node kinematics.startup_alignment_ready
ros2 param get --no-daemon /gimbal_kinematics_node kinematics.runtime_world_rotation
```

第一项为true表示首次计算已经完成，第二项为实际采用的3×3旋转矩阵，按行展开。它们是运行状态，不是安装精度验收证明；采样脚本会保存公开运行参数。

随后按[比赛启动流程](../教程/比赛启动与收尾.md)设置裁判指定ID、确认跟踪，再由裁判开始本轮。独立位置误差、真实光心偏移、银圈到真实LiDAR原点、剩余yaw安装方向及理想轴向偏差仍留作后续验证，不再要求重新测量已经交回的机械尺寸。
