# 海康相机内参标定：现场逐步操作教程

2026-10-17。环境：B的Windows运行NoMachine，连接NUC Ubuntu22.04/ROS2 Humble；已运行的相机发布`/image_raw`，1440×1080、rgb8。

**本次只标相机内参K和畸变D。** 相机与IMU之间的平移/旋转是另一项外参标定，不能靠拍棋盘格顺便得到。云台不需要转动，移动棋盘格即可。

你已确认两份标定来自同一套设备、镜头和相同设置。fx约1778与999的差异必须复查；本次重新采多姿态棋盘图、保存完整数据，再用独立测距验收，不先指定哪个数应该正确。

## 1. 教程确实提到了，应该看哪里

- [主办方第二课](https://blog.secaumene.com/teach/class-2.html)：页面搜索“相机标定/Calibration”。讲了张正友法、多角度/边角覆盖、重投影误差及YAML落地。
- 套件已有更具体的操作文档：`gimbal-edu-tools/camera_setup/CALIBRATION.md`。它的内角点、方格实测、CALIBRATE/SAVE步骤可复用；其中启动usb_cam和640×480默认配置不适用于你们当前海康相机。
- 实际命令和保存行为已对照你们导航压缩包里的camera_calibration源码核查；不是只凭教程猜参数。

原理只需先理解一句：同一台相机拍到棋盘格的多个不同倾角和位置，用这些几何约束共同求K/D。**只在画面中央正对着挪来挪去，照片再多也可能缺约束。**

## 2. A/B/C各自做什么，约30—45分钟

| 人 | 当场工作 | 留下什么 |
|---|---|---|
| A | 数内角点、测单格边长、检查覆盖计划和标定结果 | 棋盘规格、尺量照片、记录表、结果核对 |
| B | Windows NoMachine进入NUC，运行标定程序、保存并下载数据 | 终端日志、完整标定包、ost.yaml、session.json |
| C | 将棋盘保持平整，按下面顺序摆位置/倾角，每次稳住 | 多姿态采图，棋盘与相机镜头状态照片 |

时间建议：5—10分钟确认棋盘/图像，10—15分钟多姿态采样，2—5分钟计算保存，其余做第二组复采或独立测距。GUI计算慢时等待，不反复点击。

## 3. 出发前把棋盘格准备好

### A先数：内角点，不是方格数

内角点是棋盘内部四个黑白格相交的位置，最外边界不算。

```text
如果横向有9个方格，内部横向交叉点就是8个；
如果纵向有7个方格，内部纵向交叉点就是6个。
所以这块板对应8×6内角点，不是9×7。
```

让棋盘长边横放，A和C分别数一遍，记录“横向内角点____，纵向内角点____”。这不是要求你们一定换成8×6；已有棋盘数多少就填多少。

套件对应位置：`gimbal-edu-tools/camera_setup/CALIBRATION.md`的“准备”；这里已按你们海康相机的情况展开，B无需再找本地文件。

### A再量：一个黑/白方格的边长

- 量打印后实物，不采用PDF上写的尺寸。
- 可跨连续4个格量总长再除以4，例如4格总长100mm，单格25mm；横向/纵向都核对。
- 横纵明显不是等边方格，或纸张起皱、翘曲、贴歪，先换平整板，不拿不规则图案强行标。
- 纸贴在硬平板上，保留棋盘外白边；拍摄中不要弯折纸面。

记录单格____毫米。启动脚本接收毫米并换算成米，例如25mm会传给原工具`--square 0.025`，避免手动写错单位。

注意：**均匀填错单格的长度，不能单独解释这次单目标定fx约1.78倍差异。** 单位/尺寸仍应正确，但本次还要核对输入图像、采图姿态、原始K与校正后P。参见[OpenCV相机标定模型](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

## 4. B先把本队标定入口传到NUC

一起发给你的文件是：

```text
team47_camera_calibration_20261017.tar.gz
```

包内有本教程和`run_camera_calibration.py`。它使用NUC已安装的camera_calibration，不需要重新编译昨晚的四个视觉包，也不启动相机驱动。

为什么用本队入口：归档版本原工具的SAVE硬编码覆盖`/tmp/calibrationdata.tar.gz`，COMMIT会调用相机SetCameraInfo服务。本队入口只改变这两处行为：SAVE独立新建本队文件；COMMIT禁用。标定和角点算法仍是原工具，系统包不修改。

B在NoMachine远程Ubuntu按Ctrl+Alt+T，输入：

```bash
mkdir -p ~/ws_championship/team47_transfer_20261017
```

Windows NoMachine的`!M → Transfer a file → Upload file from the client`，选新压缩包，保存到上面的NUC目录。参考：[NoMachine文件传输](https://www.nomachine.com/sharing-files-between-computers)。

回NUC终端输入：

```bash
tar -xzf ~/ws_championship/team47_transfer_20261017/team47_camera_calibration_20261017.tar.gz -C ~/ws_championship/team47_transfer_20261017
export CAL_TOOL="$HOME/ws_championship/team47_transfer_20261017/team47_camera_calibration_20261017/run_camera_calibration.py"
```

第一次解压即可；同名目录已经部署过就继续使用，不重复覆盖。后面所有命令都在这个NUC终端执行。

## 5. B检查输入和标定工具；C让相机保持固定

```bash
source ~/ws_championship/src/47-vision-check-20261016/进入检查环境.bash
ros2 pkg prefix camera_calibration
ros2 topic info /image_raw --verbose
ros2 topic echo /image_raw --once --field width --qos-reliability best_effort
ros2 topic echo /image_raw --once --field height --qos-reliability best_effort
```

应看到：camera_calibration有安装路径；/image_raw有现成publisher；尺寸1440、1080。现有驱动继续运行，本轮不开第二个相机驱动。

- 找不到camera_calibration：保存这条错误和当前环境，先不在公共NUC安装依赖或重装ROS。以前标定用的终端可能加载了另一套安装环境，需要核对。
- 无publisher：先恢复已有相机数据；标定器按启动时已有发布者选择QoS。
- 尺寸不同：记录实际尺寸，查明输入路径，不能继续把这次当成1440×1080原图标定。

A/C拍相机、镜头型号和现有调焦环位置。拍板应清晰；如确需调焦，在采样开始前完成并固定，采样期间不要再调焦、变焦或改分辨率。保持本次标定对应的实际比赛图像路径。

## 6. B创建这次会话目录，输入实测棋盘规格

复制：

```bash
CAL_DIR=$(mktemp -d "$T47_RUN/records/calibration_20261017_XXXXXX")
printf '本次保存目录：%s\n' "$CAL_DIR"
read -r -p '横向内角点个数：' BOARD_COLS
read -r -p '纵向内角点个数：' BOARD_ROWS
read -r -p '单格实测边长，毫米：' SQUARE_MM
```

终端会依次问三个问题，B输入A刚确认的数。例如板确实为8×6内角点、25mm，分别输入8、6、25后回车。**这三个数用实物值，不是照抄例子。**

然后：

```bash
python3 -u "$CAL_TOOL" --output-dir "$CAL_DIR" --cols "$BOARD_COLS" --rows "$BOARD_ROWS" --square-mm "$SQUARE_MM" 2>&1 | tee "$CAL_DIR/console.txt"
```

应该打印内角点数、毫米边长、本队SAVE目录，然后弹出标定窗口。窗口右侧应有X/Y/Size/Skew进度及CALIBRATE/SAVE/COMMIT按钮。保持默认普通针孔Pinhole模型，不切换成鱼眼模型。命令中的-u让日志及时显示，tee同时把它保存下来。

- 程序报缺包/接口不匹配：保存console.txt，不自行覆盖系统依赖。
- NoMachine窗口里无画面：先确认第5部分输入正常、/image_raw全名和ROS域一致。
- 有棋盘但不出现彩色角点连线：先核对内角点数、整板是否入镜、焦点、反光和白边；C靠近一点并摆正后再试。

GUI为了显示可能缩小预览，**窗口小不代表输入变成640×480**。输出尺寸最后仍要检查。

## 7. C按这个顺序摆棋盘，A负责检查覆盖

整个棋盘始终留在图像内，手尽量不遮格。每换一个姿态停1—2秒，图案清晰后再换；缓慢移动，别连续晃动。

| 次序 | C怎么拿板 | A/B看什么 |
|---|---|---|
| 1：中间正对 | 放画面中央，整板大约占画面宽度一半 | 棋盘完整、彩色连线稳定；终端出现Added sample |
| 2：左与右 | 距离基本不变，移到画面左侧、右侧，各做数次 | X覆盖增加，外侧角点仍不出画面 |
| 3：上与下 | 移到画面上部、下部 | Y覆盖增加 |
| 4：四角 | 移到左上、右上、左下、右下，整板不要被裁掉 | 把边缘区域也采进去，补畸变约束 |
| 5：近与远 | 靠近到整板仍完整且清晰，再移远到角点仍清晰可辨 | Size覆盖增加，不靠切掉半张棋盘撑满画面 |
| 6：左右倾斜 | 棋盘中心大致留原处，让左边靠近相机、右边远离；再反过来 | 改变板法线方向，约20—40°作为起点，能识别更重要 |
| 7：上下倾斜 | 上边靠近相机、下边远离；再反过来 | 补另一方向的倾角，Skew覆盖增加 |
| 8：组合 | 在左/右、近/远处再做几种倾角 | 避免所有倾斜都只在画面中央 |

“左右倾斜”不是只把棋盘在纸面内转成菱形；要让板的一侧离镜头更近，另一侧更远。把书封面向左/右掀开一点，就是这个动作。

参考就在这里：[第二课的相机标定与成像细节](https://blog.secaumene.com/teach/class-2.html)。边角覆盖约束畸变，不同倾角帮助分清焦距、主点和每张板的姿态。

工具会挑选不同的样本。**摆了40次不等于入选40张**，看终端`Added sample N`实际数字。近乎一样的画面通常不会重复入选。

建议采到约40—60张有区别的有效样本，同时确保上述位置和倾角都有。归档版本的按钮条件是“入选样本≥40，或四项覆盖达到阈值”，所以四条不一定必须全满；按钮亮了也不能代替采图质量判断。不要为了凑数字一直重复中央正视图。

## 8. B点击CALIBRATE，再点SAVE

A检查边角、远近、倾斜都覆盖后，B点击CALIBRATE。保持程序运行，计算时等待。终端通常打印K、D及标定文本，图像会出现去畸变后的预览。

然后点SAVE。应该在终端看到：

```text
本队SAVE完成：/home/.../team47_check_20261016/records/calibration_.../calibrationdata_....tar.gz
已保存采集图像、ost.yaml和ost.txt；没有写入相机驱动。
```

本队入口即使点到COMMIT也会阻止写入，并提示点击SAVE。**这里只使用SAVE。** 不点击原生工具的COMMIT，因为它可能改相机驱动配置；--no-service-check本身不能禁止COMMIT。

保存完成后，在运行程序的终端按Ctrl+C退出。这个终端的CAL_DIR仍保留，继续下一步。

## 9. B检查保存文件，A看结果有没有明显问题

```bash
CAL_ARCHIVE=$(cat "$CAL_DIR/latest_saved.txt")
ls -lh "$CAL_ARCHIVE"
tar -tzf "$CAL_ARCHIVE" | sed -n '1,10p'
tar -xOf "$CAL_ARCHIVE" ost.yaml > "$CAL_DIR/ost.yaml"
cat "$CAL_DIR/ost.yaml"
```

应看到非零大小的归档，包含多张`left-0000.png`之类的棋盘图，还有ost.yaml、ost.txt。YAML中应有：

- image_width=1440、image_height=1080；
- camera_matrix的3×3 K，fx/fy为有限正数；
- distortion_coefficients的D。

不要给fx预设1000或1778，也不要把两份旧值平均。**这次结果是候选，尚未通过独立验收。** `projection_matrix`里的P可能和K不同，原始/image_raw的PnP要用K+D，不把P混进来。

不同版本不一定打印总体重投影RMS。你们压缩包中的实现算了它，但没有明确打印/保存该变量；GUI的linear error也不等于总体RMS。**没有看到RMS不等于标定失败，不要找不存在的一行。** 保留完整棋盘图，我可以回来计算逐图残差、检查边缘分布和异常样本。

官方建议重投影误差应在1像素以内甚至更小，可作为初筛；低误差不能单独证明真实测距正确。[主办方标定误差说明](https://blog.secaumene.com/teach/class-2.html)。

## 10. 最好再做第二组独立采样，别复用同一批图

若还有约10分钟，重复第6—9部分：创建新的CAL_DIR，重新采不同姿态，另存一包。镜头和输入设置保持不变。

A对比两次fx/fy：如果又相差几十个百分点，别随便选一份；保留两套图查退化/输入或模型问题。几%的差异也要结合误差和真实测距判断，不把“第二次接近第一次”当作唯一验收。

这次是为核查已有参数的大幅冲突而复采，不是每次到实验室都必须重新标定。

## 11. 还要留一组不参与标定的测距证据

标定后先不覆盖原程序配置。C把已知黑色外边长100mm的平整ArUco码放在两个不同距离，比如约1m和2m。A写清实际尺量值及从镜头哪一基准点量，光心偏移未知就注明。

B在另一个已source本队环境的终端，每档录3—5秒原图：

```bash
ros2 bag record -o "$T47_RUN/records/calibration_validation_near_01" /image_raw /camera_info
```

近档录完Ctrl+C，远档换名far_01再录；同名目录已有就换后缀，不覆盖。原图体积大，只录短包。/camera_info可能仍全零，因为本次没有向驱动COMMIT，这不影响保留原图与新标定文件。

这批ArUco不是用于求K的棋盘训练数据。回来用新K/D、旧K/D在**同一批实际图像**上解算，再和独立尺量比，才能判断哪份更适合当前相机。内参标定仍不能补出相机—IMU安装外参。
