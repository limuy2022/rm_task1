## 3. 关于“/dev/gimbal空链接”：先查当前事实，不猜ttyUSB0

截图表达的是一种怀疑。目前记录又显示：桥曾打印“串口/dev/gimbal，来源udev，已独占”。在本地源码中，这句只在实际open、独占及TTY配置成功后才打印。因此：

- **若NUC运行的就是这版源码，同一时刻目标不存在的悬空链接，不应打印这句成功日志。**
- 后来拔插造成链接失效，或检查与启动不是同一时间，可以出现前后不同状态。
- 字符设备不是普通文本文件。“文件大小0”或没看到文本内容，不等于无串口数据。
- 能打开一个TTY，也不证明它连接的是目标云台，或收到了正确固件协议。

源码依据：`42-gimbal_serial/src/bridge_node.cpp`的构造函数，及`src/serial_port.cpp`的SerialPort::open。

### C看设备，B在NUC终端2做只读检查

```bash
ls -l /dev/gimbal
readlink /dev/gimbal
readlink -e /dev/gimbal
stat -Lc '类型=%F 主次设备号=%t:%T' /dev/gimbal
```

按这张表判断：

| 输出 | 代表什么 | 下一步 |
|---|---|---|
| ls显示`gimbal -> ttyUSB0`之类；readlink -e给出完整目标；stat显示character special file | 当前链接指向一个存在的字符设备 | 保留完整输出，再查设备身份；先不改链接 |
| ls能看到链接，但readlink -e无输出、stat报不存在 | 可能是当前悬空链接 | 保存输出与检查时间，不执行ln -sf或随便改成某个ttyUSB |
| ls直接说没有该文件 | 当前没有这个别名 | 列出已有设备身份给后续判断，不猜目标 |
| stat显示regular file | 是普通文件，不是可用TTY | 记录；不能靠它启动真实串口桥 |

接着只查询设备身份和占用，不打开串口：

```bash
ls -l /dev/serial/by-id
udevadm info --query=property --name=/dev/gimbal
fuser -v /dev/gimbal
```

目录不存在、某命令未安装或权限不足时，保存原样输出，不为此安装或改权限。C把设备型号、连接到哪块控制板，与输出的USB标识对应起来；不要用`cat /dev/gimbal`看内容，也不要用另一个程序抢读已有桥的数据。

若桥已经运行，可只查询：

```bash
ros2 param get /robo_bridge subscribe_cmd_vel
ros2 param get /robo_bridge publish_tf
ros2 node info /robo_bridge
```

昨天用的是默认launch：本地默认不订阅运动命令，但publish_tf=true。仅接收模式也会打开和配置串口、发布会话状态；不是完全无副作用的纯查询。下次真要重启接收桥，必须先确认端口身份和已有桥状态，入口要明确关闭命令订阅与TF；**本轮先完成上面的元数据检查，不给你们一条盲目换端口重开的命令。**

协议参考就在这里：[主办方串口桥](https://blog.secaumene.com/kit/bridge.html)、[统一协议](https://blog.secaumene.com/kit/protocol.html)。

## 6. IMU坐标没画出来，接下来怎么补？

目前不需要为了补图把G轴猜成和相机平行。

- O光学系：x图像右、y图像下、z镜头向前。
- C相机系：x镜头向前、y图像左、z图像上。与O共光心，约定关系已知。
- G云台IMU系：要找到**固件输出轴映射所对应的实物方向与原点**，与PCB芯片手册轴可能不同。

**C拍什么：**云台正面/侧面/俯视各一张；IMU模块或控制板型号/丝印近照；它在底座还是随pitch运动的支架上；有无装配图/轴向标记。相机、IMU、转轴尽量同时入镜。看不见芯片时，拍可重复找到的螺孔/安装面，记代理点，不把电机中心当IMU原点。

**A做什么：**把已确定的O/C轴标在照片上；G单独列“原点/三轴/依据”四项，未知处写未知。把固件文档/轴映射与实物对应后再画G。静止加速度能给重力方向约束，不能单独决定绝对前向，也不能给光心—IMU平移。

**B做什么：**先恢复云台IMU有效数据；留原始消息的frame_id与固件定义。仅有frame_id字符串或一个单位四元数，不能完成实物轴向确认。

原理与参考就放这里：[第一课坐标与TF](https://blog.secaumene.com/teach/class-1.html)、[统一协议轴定义](https://blog.secaumene.com/kit/protocol.html)、[ROS坐标约定](https://www.ros.org/reps/rep-0103.html)。缺G会阻塞后续全局位置变换和真实控制，不阻塞现在的O系测距、角点采集与离线估计代码。
